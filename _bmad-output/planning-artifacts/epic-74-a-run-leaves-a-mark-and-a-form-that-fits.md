## The one sentence

**A copy cannot say how far it got, a run cannot say why it ran or how late, and the form you create one in does not fit on a screen — so the owner is asked to describe a date window instead of being told where the last pass stopped.**

## Decisions this epic takes

- **AD-251 — The task ledger lives in a synced folder, flagged the way the notes vault is flagged.** A profile gains `[folder.tasks] subfolder` (`TasksConfig`), validated by the `NotesConfig` rules verbatim — refused, never corrected: never empty (a ledger is a folder inside the profile, never its root), never absolute (`Path::join` discards the left side), never escaping, never inside another feature's subfolder. The selector is machine-local, `tasks.ledger_vault`, mirroring `notes.active_vault` — because a profile id is minted per machine. **Not `.keeper/`**: `BUILTIN_EXCLUDES` hides everything under it except a direct-child `*.toml` (AD-100), so a per-task tree there would never travel, which is the whole point — and epic 73 just measured what a tracked file inside an excluded directory costs (DW-255, DW-256). With no ledger folder configured nothing is invented: runs stay in `task_runs` and the surface says the ledger is not set up.
- **AD-252 — The run file's NAME is the mark; the body is for people.** `<ledger>/<task>/<year>/run-<mark>-<outcome>-<fp8>.md`, where `mark` is `YYYYMMDDTHHMMSSZ` of the **high-water source modification time the run covered** (for a kind with no source: the run's finish time), `outcome` ∈ `ok | partial | failed`, and `fp8` is the first eight hex of a SHA-256 over the task's own configuration. The next copy therefore needs **no file open and no database**: it reads directory names, takes the greatest `ok` mark whose `fp8` matches the configuration it is about to run, and copies only sources modified after it. Three rules give that its teeth: a run that was not `ok` never advances the mark; a configuration change changes `fp8`, so no mark applies and the next pass is full; and the mark is the **newest mtime actually copied**, never the clock, so a file written while the pass ran is caught by the next one instead of being skipped forever. The body is `render_copy_log`'s existing text — path, bytes, sha256, outcome per file — moved from the destination, where nothing read it, into the ledger where the surface does.
- **AD-253 — A run says why it ran, and whether it was late.** `task_runs` gains `trigger` (`scheduled | requested | timer`) and `late_by_ms`, both written at claim time, where the engine already knows them and currently throws them away. Every kind, manual included. `TaskRunVm` carries them, the runs list shows them, and the tracing line names them — so "it ran because a person asked" and "it ran 40 minutes after its window" stop being invisible.
- **AD-254 — Configuration is visible even when it is a constant, and a row nobody can drive shows no control.** Paced work renders its full configuration read-only, with every value injected by the shell rather than mirrored in TypeScript (the existing `syncPacedWork` discipline). This is display, not driving: AD-141's gate ("a projection never migrates; no schedule editor, no Run now on the projected class") and AD-142 ("a read-only projection registers no scheduler") are preserved exactly — the epic adds facts to read, never a lever.
- **AD-255 — The radius scale gains a container step.** Cards at surface scale get 10 px (`--radius-lg`-keyed, 2 × the 5 px key) while fields stay 7 px and inline chips 3 px. DESIGN.md:252's doctrine stands — a workroom's fittings are square-ish, 12 px reads consumer — but a container and the fields inside it must not carry the same corner, which is what "the corners are not quite corners" is measuring.
- **AD-256 — rescinds AD-245.** The copy date window is removed end to end, with no shim and no deprecated alias: the fields, the CLI flags, the form inputs, the generated bindings, the docs rows and `CopyOutcome::Skipped`, whose only producer it was. A date the owner has to type is a worse answer to "copy what changed" than a mark keeper writes itself.

## Stories

### 74.1 — The add form fits one screen, and a card's corner is a card's corner
AD-255, and the density half of claim 1a. The nine standing note paragraphs leave the flow for the `IconHint` idiom the header already uses (AD-240 precedent, `tasks-pane.tsx:194-200`); the copy/bot fieldsets keep their inline help only where it names a refusal. No floor constant moves, no second scroll is added, and the window minimum is untouched. The container radius step lands in `src/index.css` + DESIGN.md.
**Acceptance:** a real-browser probe (`dev/probe`, the gate spec-72-3 and spec-72-9 both left unrun) reports the add-form card's `scrollHeight ≤ clientHeight` of its region at 1568 px **with a panel open and the drawer expanded**, and at 1024 px; `window-minimum.test.ts` and `tasks-pane.test.tsx`'s floor/placement assertions stay green with no constant changed; every note that leaves the flow is still reachable (a hint test asserts the label, not the prose); the card's computed radius differs from its inputs'.
**binds:** FR-554, AD-255, AD-240

### 74.2 — The copy date window is gone
AD-256. `modified_after_ms`/`modified_before_ms` and `CopyOutcome::Skipped` deleted from `copy.rs`, `db.rs`, `engine.rs`, `keeper-core/src/tasks.rs`, the generated bindings, `task-form.tsx`, the `keeper-syncd` flags, the dev mock shell and `docs/sync.md` §14 — one cutover, no shim. The stored columns are left inert per the crate's additive-only column rule, and that is stated in the spec rather than hidden.
**Acceptance:** no occurrence of either field name anywhere outside a changelog or a ledger entry; the CLI-vs-`docs/sync.md` word-list guard passes; `keeper-sync`'s copy suite is green with the date tests removed rather than rewritten to assert nothing; `bun run check` passes with the form fields gone.
**binds:** FR-555, AD-256

### 74.3 — A folder in the drive holds the task ledger
AD-251. `TasksConfig { subfolder }` on `SyncProfile`, the `[folder.tasks]` table in the folder file with its deep overlay, `validate` copied from `NotesConfig` (empty/absolute/escaping/overlapping refused), the machine-local `tasks.ledger_vault` key in `config/keys.rs` + `docs/settings-keys.md`, and the folder-edit IPC field. Every path is composed through `browse::plain_segments` + `WriteScope::route` — AD-65: no new path arithmetic.
**Acceptance:** a folder-file fixture carrying `[folder.tasks] subfolder = "70-tasks"` round-trips and keeps sibling tables intact (the deep-overlay test's shape); an absolute, empty, escaping or notes-overlapping subfolder is refused and **not stored**; the key appears in `docs/settings-keys.md` with its scope and default; with no ledger configured every existing test still passes and nothing writes outside the database.
**binds:** FR-556, AD-251, AD-65, AD-100

### 74.4 — Every run leaves a mark whose name is enough
AD-252. The naming grammar and its parser in `keeper-core` (pure, testable, no clock, no filesystem), the writer in `keeper-sync` (atomic sibling-temp + rename, the discipline `SessionManifest::write` uses), the year subfolder, the per-task configuration file, and the copy engine's new lower bound: the greatest matching `ok` mark, read from directory names alone. `render_copy_log`'s body moves into the mark file.
**Acceptance:** a ledger fixture with three runs across two year folders yields the greatest `ok` mark from names only, with no file opened (asserted by a reader that is handed names, not paths); a `failed` or `partial` run does not advance it; a changed configuration changes `fp8` and the next pass is full; the mark is the newest mtime **copied**, proved by a fixture whose source is touched mid-pass and picked up by the following run; a torn writer leaves no `.tmp` residue and no half-parsed name; the grammar refuses characters `plain_segments` refuses and round-trips through it.
**binds:** FR-557, AD-252, AD-65

### 74.5 — A run says why it ran and how late
AD-253. `task_runs.trigger` and `late_by_ms` written at claim time (the discard at `engine.rs:3966-3975` closed), `TaskRunVm` extended, the `columns_of` schema-pinning test moved with the schema, the tracing line extended, and the mark file's name carrying the trigger word so provenance survives without the database.
**Acceptance:** a run claimed by the scheduler, one requested by a person and one served after its window produce three distinguishable rows and three distinguishable file names; `late_by_ms` is zero for an on-time run and the measured lateness otherwise, computed from the window the row actually carried before `finish_task_run` overwrote it; every kind (sync, release, verify, bot, copy, gc) is covered by the same path — no kind-specific branch.
**binds:** FR-558, AD-253

### 74.6 — Runs are a list you can open, and configuration is visible even when it is a constant
AD-254 + claims 3 and 5's display halves. Run rows become openable and drill down into the **panel strip** — the gesture `panels.ts` already has for `note|file|recording|task`, plus a `run` target — because the measured width budget has no room for a fifth fixed column and this epic does not move a floor. Every kind's run list reads the same view model; bots' `bot_audit` rows and sync's `activity` rows are surfaced as that run's detail rather than duplicated; paced rows grow a read-only configuration block with the constants injected by the shell.
**Acceptance:** a run row opens a panel whose target survives a pane switch and a reload (the `Panel.replaced` semantics its siblings have); the paced section still renders **zero** controls (a test asserts no button, no switch, no schedule field on a projected row) while showing every cadence value; a bot run's detail lists its audit rows and a sync run's lists its activity rows, both read-only; with no ledger folder configured the runs list still renders from `task_runs` and says where a file ledger would live.
**binds:** FR-559, AD-254, AD-141, AD-142

## What stays out

- **Rewriting the copy engine's dedup.** `Identical` stays content-based; the mark is a *lower bound on what to consider*, not a replacement for the check that decides whether a file needs writing.
- **A second driver for paced work.** AD-141 keeps its teeth: this epic shows paced configuration and never lets it be scheduled or driven. Any future story that gives a paced gate a schedule must surrender the gate in the same change.
- **Backfilling history into the ledger.** The first run after a folder is configured writes the first mark; nothing invents marks for runs that happened before the ledger existed, and the surface says so rather than showing an empty year.
- **Dropping the destination copy log.** It moves; it is not deleted. A copy into a folder somebody will read in five years keeps a plain-text record next to the bytes.
