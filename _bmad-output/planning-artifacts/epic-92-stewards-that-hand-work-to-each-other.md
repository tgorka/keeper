## The one sentence

**keeper's agents can each answer in their own room, but none can hand work to another, the board cannot say who works a card or where, nothing runs a card on a schedule, a change made on the server can take an hour to reach the Mac, and nothing stops a private thing from being sent to a shared room.** The fix is six parts:
- **Delegation** opens a session the target owns, bounded by hops, rounds and tokens.
- **The board** shows `run:` as a badge on unchanged columns, with who, where and for whom.
- **Scheduled cards** run on an agent host's own tick, once per window, guarded by the claim.
- **The doorbell** fetches one drive at once, and the quiet folder asks its remote every five minutes.
- **The stewards** triage, hand on and look back, with the tools every agent has.
- **Labels** are checked at every sink; only the owning person lifts a block, through their proxy.

- **Q2. Where `check_sink` lands.** AD-391 is 92.6's, but 92.1 must check a delegation before it sends, and 92.2 and 92.4 add sinks. **Plan's reading:** the pure `keeper_core::agents::label::check_sink` with every sink arm (`Model` and `External { readers }` included, R28 S-04, R24(1)) lands in 92.1; each story calls it at the sink it adds; 92.6 wires the sinks that existed before this epic (answers, drive writes, `session_write`, invites, status and scope edits, the turn's model call), adds the integrity rule, the declassification route, and the suite that tries every sink.
- **Q3. Declassification before approvals exist.** AD-391's lift is "a T3 *declassify* approval … decided through their proxy's DM"; approvals are Epic 93. **Plan's reading:** 92.6 computes the request (the exact bytes or artifact with its SHA-256, the sink, the approvers, the proxy DM it goes to) and refuses with "Letting this through needs an approval, which this keeper cannot take yet"; 93.3 sends it and records the decision. FR-795 is met when 93.3 lands.
- **Q4. Every hand-off from a private session to a shared steward is a declassification.** Nixi's sessions are labelled {tgorka} from their first line (AD-390), so `delegate(lucyna-novak, …)` is always blocked until tgorka lets that brief through. **Ruled (R25; D-34 corrected, R29 F8):** every hand-off from a proxy session to an agent with a wider audience is a declassification — the proxy's context holds its person's core memory — so the brief is shown to the person in their proxy's DM and released with one tap (93.3); the release is the recorded declassification. Before Epic 93 the block says so in one sentence.
- **Q5. The stewards' default tools.** **Ruled (R27; R29 F18), stated once here:** a steward's default set is the specialist's set plus `delegate`. 89.3's specialist set already carries `card_update` and `workflow_start` (epic 89, 89.3 *Kind defaults*), so nothing else is added, and no surface tool (AD-383 keeps those for the person's proxy). AD-397's contrary sentence is corrected in the architecture to match AD-389.
- **Q6. Where a harvest runs.** AD-404 writes candidate notes "into the session's `artifacts/knowledge/`" — a closed session owned by another agent, whose claim was released at close. A steward turn there would put a second agent's context into the first agent's log (one owner, one writer: AD-365, AD-366, AD-378). **Plan's reading** (agreed with epic 95's planner): the steward's turn runs in her **own** harvest session; 95.5 writes the notes there, under `artifacts/knowledge/<source-slug>/`, with `sources` naming the closed session.
- **Q7. `waiting` on a card.** **Ruled (R25):** `run:` gains `waiting`. A window nobody can serve is `run: waiting`; the reason (`hesperia — host offline`) is the `run` log line's `detail`, projected onto the card by the index. No other card key carries it.
- **Q8. Who writes `run: waiting` when no host can serve a card.** `run:` is written only by the owning host (R25). **Plan's reading:** the principal's live always-on host that ranks first by AD-379's order claims the card's session, writes `run: waiting` and the `run` line, and releases the claim at once.
- **Q9. A person's own session cannot carry a scheduled agent card.** "A run appends a turn to the card's own session" (AD-387), and a person's flat session has no `agent.toml`, owner or log. **Plan's reading:** a scheduled card runs only in a session of its assignee; such cards are born by `delegate(…, card: {schedule})` (Nixi does it when asked) or by a steward, and wait for a person's tick before their first run (Q16). Adjacent changed lines conflict in a three-way merge. **Plan's reading:** the host writes its keys as a block separated from `status:` and `order:` by at least one line it does not change, pinned by 92.2's merge test; DW-374 measures the rest in use.
- **Q11. "Derived from untrusted data".** AD-391 blocks a recipient, path or target argument derived from `untrusted` data. Values carry no taint today. **Plan's reading:** under `untrusted` integrity, such an argument passes only if it appears verbatim in a line of `owner` or `peer` integrity in the session (the person's message, the brief, the session's `agent.toml`); otherwise it is blocked. DW-378.
- **Q12. What an "exchange" is.** "≤ 3 rounds per exchange (a round is one message each way)". **Plan's reading:** an exchange runs from a `delegate`, or from the requester's next message after a `reply`, to the target's next `reply`.
- **Q13. The cards the stewards make for themselves.** **Plan's reading:** each steward's host creates her `triage` session with a `@daily` triage card, and her `harvest` session with its card, once: the session ids are derived from (drive, agent, `triage` | `harvest`), and the host writes a card only in the step that creates its session. - **Q14. Line drift.** The architecture cites `docs/sync.md:3478` for the remote-poll row; it is at `:3468` in this worktree, with the paragraph at `:3491-3496` (`:3478` is the `verify` proposal).
- **Q15. A drive several principals mount** (R29 F19, ruled: it rings every control room whose `agentd.toml` lists it). neuradrive is mounted by `agentd-tgorka` and `agentd-neuraffica`, whose control rooms differ, and a host can post only into a room it is in. **Plan's reading:** a zone-wide doorbell (`memory`) for such a drive is sent into the ringing host's own control room and into every other control room its ringing agent is a member of whose host manifests (`dev.keeper.agent.host`, `drives[].id`) list the drive. - **Q16. - **Q18. ## The failure shape this epic must not repeat

**A normal state shown as a fault.** A card an agent is working is a normal card. A review that finds any of the following is a blocker:
- an agent card in "Not in a column", or "Fix the key in the file" for a card whose `status:` is one of the four;
- a test changed so that `parse("blocked")` is not `None`, or a fifth entry in `STATUSES` or `BOARD_COLUMNS`;
- a `run:` value dropped instead of shown as unreadable;
- `run:` written by a tool, a person's action in keeper, or a host that does not hold the claim.

**A schedule nobody allowed.** A review that finds a card that runs while it carries `scheduled_by:`, an agent's write that removes `scheduled_by:` or `integrity:`, a `schedule:`/`workflow:` set through `card_update` or a `delegate` card without a person, or a scheduled window run twice after a takeover, is a blocker (R28 S-21, S-25).

**A second scheduler.** A review that finds a timer, an interval or a thread of the agents' own, a `TaskKind`, or a scheduled run stored in `sync.db` is a blocker (AD-62, AD-136, ruling R9).

**A doorbell that walks.** A review that finds `wake_now` called for a doorbell, a doorbell that widens the walk, or the quiet-folder test changed to pass without the fix is a blocker.

**A leak by a side door.** A review that finds a sink that does not call `check_sink` — an answer, an invite, a hand-off, a write, a card, a doorbell, a status or scope edit, a model call — or a block that sends anything, or content in a state event, is a blocker.
