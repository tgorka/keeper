# Frozen IPC contract
Rust owns consent, bounded export and public config. New types in keeper-core::telemetry (serde camelCase + ts-rs exported to existing gen path). Frontend imports generated types, never handwrites gen files.

TelemetryConsentVm = { diagnostics: boolean, productAnalytics: boolean, remoteConfig: boolean }. Default all false. No replay persistent consent here: synthetic study is session-local opt-in.
TelemetryStatusVm = { consent: TelemetryConsentVm, configured: boolean, host: string | null, installationId: string | null }. ID minted only after consent; never use Matrix/account IDs. Public config from build-time KEEPER_POSTHOG_HOST and KEEPER_POSTHOG_PROJECT_TOKEN (only phc_ public token), never personal/secure key.
TelemetryEventKind = "appReady" | "commandPaletteOpened" | "settingsOpened" | "frontendError" | "interaction".
TelemetryEventReq = { kind: TelemetryEventKind, durationMs: number | null }. No free strings. Source supplied internally, never caller name/URL/error text.
TelemetryRemoteConfigVm = { supportMessage: string | null }. Bounded plain text <=200 chars; no HTML/URLs/actions; render in diagnostics settings only when remote config consent. Fetch keeper-client-config flag payload {supportMessage:string}; shipped default null.
Commands in shell telemetry_ipc.rs, registered in existing generate_handler: telemetry_status() -> TelemetryStatusVm; telemetry_consent_set(consent: TelemetryConsentVm) -> TelemetryStatusVm; telemetry_capture(event: TelemetryEventReq) -> (); telemetry_remote_config() -> TelemetryRemoteConfigVm. All Result<_, IpcError>. Frontend wrappers names telemetryStatus, telemetryConsentSet, telemetryCapture, telemetryRemoteConfig.
Backend must enforce category even if a compromised caller invokes telemetry_capture. appReady/interaction/frontendError diagnostic category; commandPaletteOpened/settingsOpened product category. Unknown event fields refused (serde deny_unknown_fields), finite bounded durations.
Additive coordinated commands: telemetry_study_config() -> Option<TelemetryStudyConfigVm> with {host, projectToken}; telemetry_study_stop() -> (). Both Result-wrapped. Study config marks the destination active in memory; stop clears that disclosure only. Frontend must synchronously block/abort outgoing study requests and stop SDK capture before calling stop. EgressKind gains Telemetry (wire "telemetry"); existing frontend uses the backend's endpoint label.
Review correction: telemetry_study_preview() -> TelemetryStudyPreviewVm {configured: boolean, host: string|null}, Result-wrapped in shell. Pure read with no activation, token, installation ID or consent record. Study uses preview before Start; normal telemetryStatus invokes its own command directly.

Live target verified through read-only authenticated API: project 605256, name keeper, management https://us.posthog.com, ingestion https://us.i.posthog.com. Project token matches the Keeper-specific vault reference. Vault hostname is the management host; do not pass it as client ingestion host.
