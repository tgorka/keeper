## What was measured

Numbers from `review-sync-2026-09-08/evidence-hesperia.md`; code anchors from the lane reports.

1. **The folder was walked 1 371 times in one session, `scanned=155626` every time, up to 666 times in one hour, p90 5.3 s, max 60.8 s.** ~600 of those per hour are `Engine::path_durability` (`engine.rs:4982`) calling `git::repo::status_paths` = `WalkPolicy::read_only()` — dirwalk **on**, stat write-back **off**, no `claim_walk`, no floor — driven by the recording banner's 1 Hz `recordingStatus()` poll (`src/hooks/use-recording-session.ts:183-187`) with no in-flight guard. The rest are watcher wakes: `scan_due` (`engine.rs:3726-3729`) is true on every tick while a file is being written, and the only pacing is the 1 Hz tick.
2. **The watcher's path list is thrown away.** `fold_watch_events` computes every event's repository-relative path and checks it against the index (`engine.rs:3989-4004`), then records only a per-profile boolean (`watch_wake: Mutex<HashSet<String>>` of profile ids, `:1110`, `:4151`). `status_paths_excluding` already builds `:(exclude,literal)` pathspecs (`git/repo.rs:1752-1761`); gix narrows the index scan by binary search for an include pathspec's common prefix (`gix-status/.../function.rs:92-94`) and prunes the dirwalk (`gix-dir/src/walk/mod.rs:235-237`).
3. **`core.fsmonitor` and `core.untrackedCache` cannot help, and keeper destroys them.** gix 0.86 decodes the `UNTR`/`FSMN` index extensions and never consults them; `gix-index/src/write.rs:117-128` writes only `tree`+`sparse`, so keeper's stat write-back deletes a user's untracked cache and downgrades `index.version=4` to v2. `index.skipHash` is honoured on read and write and is unset (every walk SHA-1s 26.4 MB, twice when it writes back).
4. **The remote was unreachable for six days and the folder never said so.** `tcp connect error: deadline has elapsed` (gix-transport's own 20 s connect timeout) matches none of the ten needles in `git/cli.rs:1109-1120`, so `git::fetch::classify` falls through to `SyncError::Git`; `record_failure` sets `Offline` only for `Network` (`engine.rs:5314-5317`); `remote_within_reach` (`:3504`) never gated; three profiles each paid the timeout serially per retry (615/549/559 attempts). The "failed N times in a row" counter is reset by the same tick that increments it (`:5320` vs `:2198-2200`), so `NeedsAttention` never fired. The offline transition is logged at `debug!` (`:5318`), which no shipped build emits.
5. **A modify/delete divergence livelocks a profile forever.** Measured against keeper's exact merge vector (`cli.rs:832-857`): modify/delete, rename-vs-modify, file/directory and case-only (`core.ignorecase=true` on hesperia) all exit 1 leaving `MERGE_HEAD`; every later `merge` and `merge --ff-only` exits 128. No `MERGE_HEAD`/`--abort` handling exists; `SyncError::GitCommand` is `Transient`; `write_tree_from_index` skips unmerged entries (`commit.rs:530-532`). `conflict::resolve` — the whole AD-43 matrix, exhaustively tested — has **zero** production callers.
6. **`lfsPruneLocal` deletes without the remote's word.** `prune.rs:38-42` names the remote confirmation as the caller's job; the one caller (`engine.rs:9112-9115`) supplies conditions 1 and 2 and stops. `audit.rs:20-26` records the gate it relies on failing in the field (16 objects, 8.0 GB missing on the server while both folders reported clean). Default on since 0.8.12; live on all three profiles.
7. **A control file can still become a pointer.** `GIT_CONTROL_FILES` (`stage.rs:110`) guards only the size path (`LfsPolicy::applies`); the attribute path (`already_routed`, `:1443-1459`) and the repair sweep have no guard, and `ensure_attributes` only appends. hesperia's `.gitattributes` lines 114–115 still carry two anchored `…/.gitattributes filter=lfs` rules from the 2026-08-27 incident (1 314 669 gix warnings). `.lfsconfig`, `.keepervirtual` and `.keeper/*.toml` are not protected at all; a pointer-text `.keepervirtual` parses as three legal globs and authorizes nothing (`virtual_policy.rs:196-268`).
8. **The gate's proof is not on the commit path.** `open_writer_veto` has no caller; `verify_while_reading` is called only by the audit verb; non-LFS staging is a bare `std::fs::read` (`commit.rs:241`). `declare_settled` backdates both clocks past the 60 s ceiling and `observe` never resets `pending_since_ms` (`stability.rs:243-259`, `:411-419`), so an asserted or primed path is `Stable` for life; `forget_all` (documented for detach/pause) has no caller. Nothing re-checks the volume between the walk (up to 61 s) and the commit; the only mass-deletion guard (`commit.rs:191`) fires only for an empty index.
9. **A fetch has a connect timeout and nothing else; a `git` child has nothing.** `gix-transport/.../reqwest/remote.rs:63-65`; `cli.rs:617` `command.output()`; no `http.lowSpeedLimit`. With no stored credential, fetch installs no callback and gix falls through to the machine's `credential.helper` chain (`fetch.rs:157-171`) — `clone` and the shim both clear it (`repo.rs:569`, `cli.rs:693-700`).
10. **A tick is serial and inline.** `tick` iterates profiles in order (`engine.rs:2192-2202`); the walk, repo opens, `prune_lfs_store` and the first clone run on the async worker; every scan enqueues a `Pull` (`:12855`); every successful pull/push runs a 155 k-path prune plan that re-opens the index per path (`stage.rs:963-967`); `wake_now` resets the hourly footprint sweep (`:10102-10114`), which is a second 155 k `lstat` pass to re-report a number it calls permanent.
11. **Nothing maintains either store.** `GitCli::gc` (`cli.rs:305`) and the three `worktree_*` verbs have no production caller; gc on hesperia is a launchd cron the owner wrote. `materialized` holds 89 289 rows, is never pruned and survives `delete_profile` (`db.rs:1686-1702`, non-transactional). `enqueue_unique` dedups on an unindexed TEXT payload (`db.rs:2009-2013`) from a per-object loop. The log has no rotation and no per-target filter; 1.9 M of its 4.35 M lines are two gitoxide targets.
12. **On the Mac a materialized row counts down to a release the platform cannot perform.** `probe_open_file_state` is constant `Unknown` off Linux and `release_resolved` refuses `OpenUnknown` — after hashing up to 1 GiB and calling the server; `release_schedule` has no platform term and the Files pane shows "23 hr". This is `tgdrive-light`'s exact configuration (`virtualOverBytes=1 MiB`, `releaseTtlMs=24h`).
13. **The spec is below the machine.** NFR-23 is 100 000 files / 50 GB; the measured row is 100 000 files / 393 MB on Linux SSD; the folder is 155 626 entries / ~450 GB on USB APFS. No requirement bounds walk *cadence*. `docs/sync.md` §18 claims "verified against real git remotes" while story 31-4 is `in-progress`; §7's linked worktree is a `git switch -c`; §11's "only place a client is built" excludes the fetch path. The store choice (git) was never recorded as a decision.

## The one sentence

**The engine spends the whole tree on every event and the whole retry budget on a remote it cannot see — because the one signal it already has (the watcher's paths) is thrown away, the one word it already has (`Offline`) is never reached, and four guarantees it already wrote down (abort a failed merge, prune only what the server holds, never pointer a control file, verify what you commit) are functions nothing calls.**

## Decisions this epic takes

- **AD-227 — A walk costs what changed.** The watcher's paths are kept, per profile, in a bounded set (`WATCH_PATHS_CAP = 4096`; overflow, a rescan event, the first pass of a run, a degraded watcher and the untracked sweep all mean *full walk*), and handed to the walk as `:(literal)` **include** pathspecs beside the existing exclusions. `WalkPolicy` gains the include list and a `read_only_tracked()` shape (no dirwalk, no write-back) for callers that never read `status.untracked`. `path_durability` answers from one `entry_by_path`, one `lstat` and the HEAD tree entry — no walk. Event-driven walks get a floor: a wake for a path the gate already holds with a future `stable_at_ms` does not set `scan_due`; between two wake-driven walks at least `min(effective_settle_ms, 5 s)` passes. `index.skipHash=true` is written beside `index.sparse=false`. The `status walk finished` line names `caller`, `untracked` and `needs_update`.
- **AD-228 — Offline is a word the folder reaches.** `git::fetch::classify` classifies by error *type* first (a connect or timeout error anywhere in the gix error chain, `io::ErrorKind::{TimedOut, ConnectionRefused, ConnectionReset, NotConnected, HostUnreachable, NetworkUnreachable}`) and by substring second, with `tcp connect error`, `deadline has elapsed` and bare `timed out` added; a fetch is bounded by a `tokio::time::timeout` (`FETCH_DEADLINE = 10 min`) that sets `interrupt` and yields `Network`; every `git` child has a deadline (`GIT_DEADLINE = 10 min`, kill on expiry → `Network`) and runs with `-c http.lowSpeedLimit=1000 -c http.lowSpeedTime=60`; the transient-failure counter is reset where a *unit* succeeds and incremented where a unit fails, never by `tick`; the `Offline` transition (in and out) is logged once at `info`. A fetch with no stored credential opens the repository with `credential.helper=` overridden and installs `static_credential` unconditionally, answering "no credential" so the failure is `Auth`, never somebody else's account.
- **AD-229 — A merge that does not finish is undone, and the matrix decides.** `merge_theirs` and `merge_ff_only` run `git merge --abort` on any non-zero exit before returning; `commit_local` refuses while `MERGE_HEAD` exists (`SyncError::Refused`, sentence names the file); `converge_with_conflict_copies` classifies each contested path into `ChangeKind` from the three `diff --name-only` sets it already has and applies `conflict::resolve` explicitly — modify/delete, rename-vs-modify, file/directory and case-only are resolved per AD-43 (`git checkout --theirs|--ours -- <path>` + `git add`) *before* `-X theirs` is asked the one question it can answer; conflict copies are staged and committed in the same commit as the merge, created with `create_new` and a numeric suffix on collision, named from raw path bytes.
- **AD-230 — A control file is never a pointer, from any door.** One predicate, `lfs::stage::is_control_file` (the union of today's `GIT_CONTROL_FILES` and `virtual_policy::is_control_file`: `.gitattributes`, `.gitignore`, `.gitmodules`, `.lfsconfig`, `.keepervirtual`, anything under `.git/` or `.keeper/`), consulted by `LfsPolicy::applies`, `already_routed`, `mismatched_filtered_paths`, `unconverted_after_repair` and `ensure_lfs_rule`; `ensure_attributes` retires a keeper-written managed-block rule whose pattern resolves to a control file or to an extension the profile's `lfsNever` excludes; `already_routed` consults `lfsNever`; `VirtualPolicy::compile` refuses text that `Pointer::parse` accepts; an `Anomaly` is raised once per pass naming any tracked control file whose worktree bytes are a pointer.
- **AD-231 — Prune releases only what the remote is known to hold.** `prune_lfs_store` restricts its plan to oids carrying a `synced_at_ms` memo (`db::synced_oids`, written by `note_unit_synced`) and runs only on a pass in which an LFS unit completed or on the hourly release look — never on every successful pull. §8 and §20 say what is enforced.
- **AD-232 — The gate's proof is on the commit path.** Non-LFS staging reads through `verify_while_reading` (a changed `FileSample` between open and EOF is `Integrity` → skip this path this pass, warn once); `open_writer_veto` is consulted from `is_stable` where `/proc/locks` exists; `observe` restarts `pending_since_ms` on a changed sample (an assertion or prime clears on its *next* verdict and never again for new bytes); the detach arm of `tick_profile` calls `forget_all` and clears `file_state`; `collect_stable_changes` re-asserts the volume marker after the walk for a `removable` profile and refuses (`MediaAbsent`) if it is gone; `stage_and_commit` refuses a change set whose deletions exceed `MASS_DELETION_FRACTION = 0.5` of the index on a removable profile (sentence: "keeper will not record N deletions from a drive that may have been unplugged; recheck the folder"); `prime_moved_paths` sets `untracked_appeared`.
- **AD-233 — One folder does not stall another, and a pass does its own work.** `tick_profile` runs per profile in a `JoinSet` (the `busy` reservation already makes it safe; `run_due_tasks` stays serial); `scan_and_enqueue`, `commit_local`, `finish_first_checkout` and `prune_lfs_store` run in `spawn_blocking`; the paced scan enqueues `Pull` on its own clock (`REMOTE_POLL_MS = 300 000`, or immediately when a push is queued or a wake named a path) instead of per scan; `pollIntervalMs` acts as a 300 s backstop while the watcher is `Live` and as itself otherwise; `wake_now` clears only `next_scan_ms`; the footprint anomaly is memoised on `(HEAD, threshold)`; the `gates` map holds one `Arc<Mutex<StabilityGate>>` per profile and no repository is opened under it.
- **AD-234 — Both stores are maintained by keeper.** `TaskKind::Gc` (closed vocabulary extended by one of keeper's own verbs: `GitCli::gc` behind the profile reservation and a quiet window), created by default weekly for every desktop profile on migration, listed and run by the same tick, refused on the phone; `materialized` rows with `released_at_ms` older than 90 days are aged out on the success edge; `delete_profile` deletes its ledger rows in one transaction; `journal` gains a `(profile_id, payload)` index; the log filter carries `gix_attributes=error,gix_worktree_state=error,gix_dir=warn` and the file rotates at 64 MiB keeping two generations.
- **AD-235 — A countdown that cannot end says so.** `ReleaseSchedule::Held { platform }` (word "Held", sentence naming the platform) is selected when `open_file_state` cannot answer, probed once per `release_schedules` call; `release_resolved` takes that cheap probe immediately after `release_path_gate` and refuses `OpenUnknown` before hashing or calling the server; a `NotTracked` refusal retracts the ledger row; the sweep opens the repository once per pass. The word is added to `FILES_RELEASE_REFUSED_HOLDS`.
- **AD-236 — The record says what runs.** NFR-23 is re-authored as *200 000 files / 500 GB / 100 000 LFS objects on removable APFS*; NFR-61 bounds cadence (*a folder under continuous single-file write costs at most one full-tree walk per minute*); NFR-62 bounds silence (*no network leg may wait longer than its deadline without a word in the log*); `docs/decisions.md` D-18 (the next free number today; 69.6 will renumber its own) records the store decision with its assumptions and revisit triggers; `docs/sync.md` §3 (order), §7 (a branch, not a worktree), §11 (which legs `keeper_sync::http` covers), §18 (only what is proven), §19 (the reference folder and the cadence multiplier), §20 (fsmonitor/untrackedCache/v4 are inert and undone by keeper; prune's real condition) are corrected; the `status walk finished` line is documented.

## Stories

### 70.1 — A walk that costs what changed
AD-227. `path_durability` without a walk; `WalkPolicy::read_only_tracked`; the bounded watcher path set and include pathspecs; the wake floor; `index.skipHash`; the log fields; the client-side in-flight guard on the 1 Hz poll.
**Acceptance:** a Rust test proves a wake naming one path walks a fixture of 10 000 entries with `scanned ≤ 2` (the include pathspec narrows the index range) and that overflowing `WATCH_PATHS_CAP` produces one full walk; `path_durability` on a committed path takes no walk claim (counter test: `status_walks` unchanged) and answers the same as before for present / modified / missing; a wake for a settling path does not set `scan_due` (test on the gate deadline); two wakes 1 s apart produce one walk; `index.skipHash=true` appears in a freshly enforced config; the frontend test asserts the poll skips a tick while one is in flight. **Measured on hesperia after install: walks per hour on `tgdrive` during a recording, before (666) and after (≤ 60).**
**binds:** FR-513, FR-514, FR-515, NFR-61, AD-227

### 70.2 — Offline is a word the folder reaches
AD-228. Type-first classification; the fetch deadline; the `git` child deadline and low-speed limits; the counter fixed where units succeed and fail; the transition logged; the credential override on fetch.
**Acceptance:** a test feeds the exact hesperia string `fetch from electra failed: An IO error occurred when talking to the server: error sending request for url (…): client error (Connect): tcp connect error: deadline has elapsed` and asserts `SyncError::Network`; a test drives `tick()` three times against a failing unit and asserts the warning and `NeedsAttention`; a fetch against a listener that accepts and never answers returns `Network` within the deadline (real socket, test-scoped deadline); a `git` child that sleeps past the deadline is killed and classified `Network`; a profile with no credential and a repo-scope `credential.helper=!false` fetches with `Auth`, never running the helper (the helper writes a sentinel file; the test asserts it is absent); the log carries one `sync offline` and one `sync reachable again` at `info`. **Measured on hesperia: with the remote blocked (pf rule), the folder card reads offline within one poll and `status_walks` stops growing.**
**binds:** FR-516, FR-517, FR-518, NFR-62, AD-228

### 70.3 — A merge that does not finish is undone, and the matrix decides
AD-229. `merge --abort` on failure; the `MERGE_HEAD` precondition; `conflict::resolve` driven from the three diff sets; the `checkout --theirs|--ours` + `add` verbs; conflict copies committed with the merge; collision-safe, byte-faithful copy names.
**Acceptance:** the lane's conflict matrix becomes a test file driving real `git`: modify/delete both ways, rename-vs-modify, file/directory, case-only, add/add, delete/delete, modify/modify (text, binary, pointer/pointer) — each ends with rc 0, no `MERGE_HEAD`, the tree AD-43 predicts, and the conflict copy (where one is due) **in the merge commit**; a fixture left with `MERGE_HEAD` by an old keeper is aborted on the next pass and syncs again; a second pass within one second does not overwrite the first copy; a non-UTF-8 path gets its own copy.
**binds:** FR-519, FR-520, AD-229, AD-43

### 70.4 — What must never become a pointer, and what must never be pruned
AD-230, AD-231. The one control-file predicate at every routing door; rule retirement; `lfsNever` on the attribute path and in `ensure_lfs_rule`; the pointer-text refusal in `compile`; the control-file anomaly; prune restricted to `synced_at_ms` and to passes that moved an LFS unit.
**Acceptance:** with a stale anchored `/a/b/.gitattributes filter=lfs` rule in the managed block, a commit of that path stores text, the rule is gone from the block after the pass, and the user's own lines above the marker are byte-identical; `.lfsconfig`, `.keepervirtual` and `.keeper/keeper.toml` over the threshold stay blobs though `*.toml filter=lfs` exists; a `.keepervirtual` whose bytes are a pointer makes `compile` return `Config` naming the file; a pointer-text `.gitattributes` in a fixture raises the anomaly with the path and the subtree; an object with no `synced_at_ms` is never in the prune plan, one with it is; a successful pull that moved no LFS unit runs no prune (counter test). **Checked on hesperia after install: `.gitattributes` lines 114–115 retired by the first pass; `git check-attr` on those two paths answers `unspecified`.**
**binds:** FR-521, FR-522, FR-523, AD-230, AD-231

### 70.5 — The gate keeps its promises
