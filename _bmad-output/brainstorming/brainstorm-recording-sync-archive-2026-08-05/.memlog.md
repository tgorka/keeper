- (direction) Grounded first: three read-only scouts mapped recording, sync and archive/notes before ideating
- (insight) Session folder is created host-side in Rust (keeper/src/ipc.rs recording_start); the Swift sidecar only derives sibling segment paths from the one absolute path it is handed — so naming and nesting are a pure Rust change
- (insight) recording.destination_dir already exists end to end (keeper.db settings k/v -> RecordingSettingsVm.destinationDir -> RecordingDestinationControls); the configurable ROOT is done, the NAME PATTERN is not
- (insight) SegmentClosed{index,path,bytes,track,ptsStart,ptsEnd} lands in the driver sink in ipc.rs after the Swift writer's finishWriting; nothing is notified — that closure is the one seam for sync-on-finalize
- (insight) SyncProfile already carries notes: Option<NotesConfig>{subfolder, journal_template, cadence} and Engine::watch_tap already fans watcher events out to notes_vault::start — recordings should copy that shape, not invent one
- (insight) No 'this path is finished, sync it now' API exists: StabilityGate::is_stable is the only gate, note_close_write (1s window) is private and Linux-only
- (technique) started Job to Be Done
- (idea by coach) The job is not tidiness: it is never losing a recording and finding it later by what it was about — naming and placement are retrieval features
- (idea by coach) Date-first folder names (2026-08-05 1432 standup) sort chronologically in Finder, ls and Files.app alike, with no metadata read
- (idea by coach) A year folder keeps the root listing small; Finder and any git status slow down long before a heavy recorder's tenth year
- (idea by coach) Month nesting should be available but not default — 2026/08/ is right for someone recording daily, wrong for someone recording monthly
- (idea by coach) Express naming as a token template, not a boolean: {yyyy}/{yyyy}-{mm}-{dd} {HH}{MM} {slug} makes year nesting fall out of the default template
- (idea by coach) Steal the token vocabulary already shipped in keeper-sync: DEFAULT_JOURNAL_TEMPLATE = journal/{yyyy}/{yyyy}-{mm}-{dd}.md — one convention across notes and recordings
- (idea by coach) Time as 1432 or 14-32, never 14:32: a colon is illegal on exFAT, and removable-volume sync makes a FAT pendrive a real destination
- (idea by coach) An untitled session must collapse the {slug} token cleanly — no trailing separators, no 'Untitled' litter
- (idea by coach) Second job: 'is this recording safe off my laptop yet?' — a per-session sync state (local / staged / pushed / verified) answers it
- (idea by coach) Third job: 'get the last hour to a colleague now' — that is a push-only lane and a URL, not a full bidirectional sync
- (idea by coach) The user's real deadline is 'before the laptop is lost': the metric to optimise is time-to-durable per segment, not throughput
- (idea by coach) Reviewing later means jumping to a moment — the ledger already stores ptsStart/ptsEnd per segment, so chapters are almost free
- (idea by coach) Nobody names a folder before a meeting starts: naming must be editable afterwards, and the rename must move the folder, rewrite the manifest and git mv in one operation
- (idea by coach) If the destination is inside a synced tree, syncing must be automatic — a second 'also sync this' toggle is a job the user did not hire us for
- (idea by coach) Job for later-me: 'what did we decide?' — that is a note keyed to the recording, not another video player
- (technique) started Morphological Analysis
- (idea by coach) Parameters of the design space: root location x path template x year/month depth x per-session subfolder shape x sync profile x subfolder in repo x LFS mode x retention
- (idea by coach) Root option A: a plain folder outside any repo (today) — simplest, syncs nothing
- (idea by coach) Root option B: root IS a sync profile's local_path — recordings become just files in the repo, zero extra wiring
- (idea by coach) Root option C: root is a subfolder of a profile (profile.recordings.subfolder, exactly like NotesConfig.subfolder) — the recommended shape
- (idea by coach) Root option D: two roots — a fast scratch volume for live writing and a synced root the finished session is moved into on stop
- (idea by coach) Template depth 0: flat {yyyy}-{mm}-{dd} … — fine to year 3, painful after
- (idea by coach) Template depth 1: {yyyy}/ — the default we want
- (idea by coach) Template depth 2: {yyyy}/{mm}/ — an opt-in for daily recorders
- (idea by coach) Template depth by profile: a synced root may want {yyyy}/{mm} while a local scratch root stays flat — so the template belongs to the destination, not to the app
- (idea by coach) Session folder shape A: one folder per session holding segments + manifest (today)
- (idea by coach) Session folder shape B: session folder plus a sidecar .md note file next to it — the note is the thing notes-sync already knows how to render
- (idea by coach) Session folder shape C: session folder inside, note file in a notes vault, linked by session id — better for note search, worse for a single self-contained artifact
- (idea by coach) Sync mapping A: whole recordings root in one profile; mapping B: per-recording routing by tag (client work to one repo, personal to another)
- (idea by coach) LFS axis: mp4 segments are always over the 4 MiB threshold, so lfs::stage::applies auto-tracks *.mp4 — the interesting cell is lfs_mode = PointerOnly on the laptop so old bytes can be pruned locally but stay on the remote
- (idea by coach) Retention axis crossed with sync state: prune locally only what is verified present on the remote — the matrix cell that makes a 500 GB/year habit survivable
- (idea by coach) Untried configuration worth naming: synced manifest.json + notes, LFS-pointer-only video — the searchable archive travels everywhere, the bytes stay where there is room
- (technique) started TRIZ Contradiction
- (idea by coach) The contradiction: syncing sooner improves durability but breaks the completeness gate, which exists precisely because a file being written must not be committed
- (idea by coach) Resolve it by segmenting in time, not by weakening the gate: a rotated segment is immutable forever, so it is not 'quiescent yet', it is FINISHED — a different fact
- (idea by coach) So add an assertion API, not a shorter timer: StabilityGate::note_finished(path) marks a path complete from an authoritative producer and skips the settle window
- (idea by coach) Authority must be narrow: only a producer that owns the writer may assert, so the API takes a path the recording driver just closed, never user input
- (idea by coach) The Linux IN_CLOSE_WRITE fast path already encodes this idea (note_close_write, 1s) — generalise it from an OS signal to a first-class producer signal, macOS included
- (idea by coach) Second contradiction: the user wants the file safe immediately, but pushing a 2 GB LFS object mid-meeting eats the uplink the meeting is running on
- (idea by coach) Win both with a two-speed policy: commit + LFS-stage locally at once (cheap, durable on the same disk), defer the push to a bandwidth window or session end
- (idea by coach) Third contradiction: one manifest.json per session must be re-written on every rotation, but rewriting the file the sync engine just committed causes churn and self-echo
- (idea by coach) Resolve by append-only: segments.ndjson grows by one line per rotation and never rewrites; manifest.json is written once at finalize
- (idea by coach) Fourth contradiction: the archive wants everything indexed, the drive wants nothing wasted — index metadata (tiny, always synced) separately from media (huge, optionally pointer-only)
- (idea by coach) Fifth contradiction: a recording must survive a crash, but crash recovery scans orphaned segments AFTER restart, while sync may have already committed a half-written file
- (idea by coach) Resolve with an in-progress marker: write segments under a .partial suffix that tier-0 name exclusion already ignores, and rename on close — atomic rename is the completeness signal
- (idea by coach) A rename is also exactly what git sees as add+delete, so the exclusion pattern must be the SUFFIX rule, cheap and total
- (idea by coach) Sixth contradiction: the user wants a friendly editable title, git wants stable paths — resolve with an immutable session id inside the manifest and a mutable display title
- (idea by coach) Then a rename is a git mv of a folder whose identity never changed, and the archive row keeps pointing at the same session
- (technique) started Chaos Engineering
- (idea by coach) kill -9 during rotation: the .partial segment is never renamed, so sync never sees it and startup recovery finalises or discards it — the failure is contained by naming alone
- (idea by coach) Disk full mid-segment: the existing disk-space guard stops and finalises; the sync assertion must fire for what WAS written, not for the segment that failed
- (idea by coach) Pendrive unplugged mid-push: absence semantics already pause without deleting — but a recording still writing into an absent volume must fail loudly, not silently buffer
- (idea by coach) Remote rejects the push (protected branch): the session must still be marked locally durable, and the tray must say 'recorded, not pushed' rather than a generic error
- (idea by coach) LFS object upload dies at 90%: resumable download exists, but a resumable UPLOAD is the untested leg for a 40 GB day
- (idea by coach) Two machines recording into the same synced folder at once: session ids must be device-scoped or the folder names collide on the same minute
- (idea by coach) Clock skew across devices: a date-first name from a machine with a wrong clock sorts into the wrong year — stamp the manifest with both local time and a monotonic device sequence
- (idea by coach) The sync engine's own commit touches .gitattributes when the first mp4 appears; if that lands mid-recording the working tree changes under the recorder — write the LFS rule at session start, not at first segment
- (idea by coach) A user renames the session folder in Finder while recording: the driver holds absolute paths, so writes keep landing in the moved folder while the UI shows the old one — detect via inode and refuse or follow, but never silently split a session
- (idea by coach) Sync pulls a remote deletion of a session the laptop is recording into — pause and warn; never let a pull delete an active session folder
- (idea by coach) The 4 h soak crossed with sync: 4 hours of 500 MB segments is ~48 commits and ~24 GB of LFS; the journal must not grow unbounded and the push must be batched
- (idea by coach) Battery dies with segments committed but not pushed: on next boot the outstanding-upload gate (lfs_uploads_outstanding) must resume before any new pointer is published
- (idea by coach) A corrupted segment (verify-on-read tier 4 catches it) must not be silently synced — quarantine it and mark the session degraded in the manifest
- (idea by coach) The webcam file and the screen file finalise at different instants; asserting each independently is right, but the session is only 'complete' when the ledger says every track closed
- (idea by coach) Deliberate abuse: a user points the recordings root at the notes vault subfolder — validate for overlap the way NotesConfig::validate already refuses .obsidian and escaping subpaths
- (technique) started Ecosystem Thinking
- (idea by coach) Map the players: the Swift recorder produces, the ledger accounts, the sync engine transports, the notes vault interprets, the archive remembers, the tray narrates
- (idea by coach) Nobody currently eats the recorder's output — the manifest is written and never read back except for meta.title; that dead end is the whole opportunity
- (idea by coach) The decomposer is missing: nothing prunes, nothing summarises, nothing ages a recording out — an ecosystem without decay fills up and dies
- (idea by coach) The obvious symbiosis: notes/tags.rs already has a hierarchical tag tree and a tag: search predicate scoped to markdown vaults; recording tags are a raw comma-split string with no vocabulary
- (idea by coach) Unify the vocabulary: one tag tree, two producers — a recording tagged client/acme shows up in the same TagTree sidebar as a note tagged client/acme
- (idea by coach) The join key is a session id; a note referencing it makes the recording searchable by the note's full text, which the archive already indexes with FTS5 trigram
- (idea by coach) Feed the archive a new row kind: a recordings table beside events, sharing the db and the FTS pattern rather than a second search engine
- (idea by coach) Emergent surface: a Recordings browser that is really an archive query — filter by tag, participant, date range, sync state
- (idea by coach) Cross-pollination: the sync engine's provenance trailer already names the device that made a change; a recording commit therefore self-documents which machine recorded it
- (idea by coach) The tray is the shared nervous system: recording state already wins the icon over sync state; extend the same composition to say 'recording, 2 segments awaiting push'
- (idea by coach) A recording session and a Matrix room are natural partners — record a call, attach the session id to the room, and the archive can put transcript, chat and video on one timeline
- (idea by coach) Predator: disk pressure. Prey: old local bytes. Defence: LFS pointer-only + prune verified objects, which the ecosystem can do because the remote is the durable copy
- (idea by coach) Niche nobody fills: the post-meeting minute — the moment the user is most willing to type two sentences of context, and the only moment they ever will
- (idea by coach) So the finalize event should also open a tiny note stub prefilled with title, date, participants and tags, saved next to the session and synced with it
- (idea by coach) Decay policy as a first-class citizen: keep media 90 days locally, keep metadata and notes forever — the archive stays complete while the disk stays sane
- (technique) started Assumption Reversal
- (idea by coach) Assumption: recordings live in one root. Reversed: routing per session by tag — a client recording lands in the client's repo, personal ones stay local
- (idea by coach) Assumption: the recorder chooses the path. Reversed: the DESTINATION chooses the layout, and the recorder asks it for a path — which is what makes per-profile templates work
- (idea by coach) Assumption: sync happens after recording. Reversed: sync happens DURING, per finished segment — which is exactly the ask, and only safe because segments are immutable
- (idea by coach) Assumption: a session is a folder. Reversed: a session is a row, and the folder is one materialisation of it — that is what makes rename, move and prune tractable
- (idea by coach) Assumption: the manifest is the record. Reversed: the manifest is a cache of the record; the durable record is the append-only ledger plus the archive row
- (idea by coach) Assumption: tags are strings on a session. Reversed: tags are edges in one project-wide tag tree that both notes and recordings hang off
- (idea by coach) Assumption: the user reviews recordings in a player. Reversed: they review them in search results, and the video is the last resort
- (idea by coach) Assumption: everything must sync. Reversed: metadata always syncs, media syncs by policy — the cheap thing is the useful thing
- (idea by coach) Assumption: the sync engine decides when a file is ready. Reversed: a producer that owns the writer knows better and may say so
- (idea by coach) Assumption: git is a bad fit for video. Reversed: with LFS pointer-only and per-extension auto-tracking it is a perfect fit for an append-only archive of immutable segments
- (idea by coach) Assumption: the year folder is for humans. Reversed: it is for git and Finder performance; humans use search — so nest for the machine and surface for the human
- (idea by coach) Assumption: naming needs a UI. Reversed: naming needs a template string and one good default; the UI is a preview of the rendered path
- (idea by coach) Assumption: a recording is a private artifact. Reversed: the push-only lane makes it a publishable one, with the provenance trailer as its signature
- (technique) started Time Horizon Ladder
- (idea by coach) Year 1: 200 sessions, 400 GB — a flat root already hurts; the year folder and pointer-only mode are enough
- (idea by coach) Year 1 risk: the first 40 GB day teaches the user that a push during a meeting is unacceptable — the bandwidth window must exist early
- (idea by coach) Year 3: 1.5 TB and the laptop can no longer hold it; local prune of verified objects becomes mandatory, and 'which sessions are local?' becomes a real UI question
- (idea by coach) Year 3: the archive is now the product — 'find the call where we agreed the API shape' matters more than any recording feature
- (idea by coach) Year 5: the repo has 5000 commits of pure media; git gc and shallow clones matter, and a second peer joining must be able to fetch metadata only
- (idea by coach) Year 10: formats rot — HEVC of 2026 is fine, but the manifest must record codec, resolution and fps so a future transcoder knows what it has (the recording settings already carry all three)
- (idea by coach) Year 10: the tag tree is the only navigation left that still works; folder names are archaeology
- (idea by coach) 100 years / the anthropologist's view: what survives is the ndjson ledger and the markdown notes — plain text outlives every container format, which argues for writing metadata as text beside the media, not only in a database
- (idea by coach) Backcast from that: the very first move is to make the session folder self-describing in plain text, because everything later reads it
- (idea by coach) Near-term corollary: manifest.json must be stable, documented and versioned from day one, since it becomes the migration surface
- (idea by coach) Ten-year corollary: never bake absolute paths into the manifest — a synced archive is opened on another machine by definition
- (idea by coach) Retention as policy text in the profile, not code: keep_media_days, keep_metadata_forever, prune_only_if_verified
- (direction) Divergence spent at 101 ideas; converging with affinity clustering, then MoSCoW because this is a build scope
- (decision) Cluster A — Path & naming: one token template renders the whole relative path, so year nesting is a default template rather than a flag
- (decision) Cluster B — Sync binding: recordings hang off a SyncProfile the way notes already do (profile.recordings.subfolder), validated against overlap and escape
- (decision) Cluster C — Finalize to durable: .partial suffix while writing, atomic rename on close, a producer assertion that skips the settle window, commit now / push on policy
- (decision) Cluster D — Session as a row: a recordings table + FTS beside the message archive, making sessions searchable and listable instead of write-only manifests
- (decision) Cluster E — Notes & tags: one hierarchical tag vocabulary shared with notes, plus a prefilled note stub written at finalize when the user is still willing to type
- (decision) Cluster F — Lifecycle: pointer-only media, prune only what the remote verifiably has, keep metadata forever
- (decision) MUST: path template with {yyyy} default nesting; recordings bound to a sync profile + subfolder; .partial + assert-finished so a closed segment syncs without waiting on quiescence; commit immediately, push on a policy that never fights the meeting's uplink
- (decision) SHOULD: recordings table + FTS + a browser; note stub at finalize; unified tag tree; rename that moves folder, manifest and git in one operation
- (decision) COULD: retention/prune of verified objects; per-tag routing to different profiles; chapters from the segment ledger; linking a session to a Matrix room
- (decision) WON'T this pass: transcription or any AI processing, cross-device dedup, a public publishing lane
- (decision) Decisive reasoning: MUSTs are the user's four explicit asks and are all reachable through seams that already exist (settings k/v, NotesConfig precedent, watch_tap, SegmentClosed sink); SHOULDs are what make the archive worth having; COULDs need policy choices best made after the first month of real use
- (insight) Synthesis: the four asks are one idea wearing four hats — a recording session must stop being a folder the app writes and forgets, and become an addressable, self-describing record whose path, durability, searchability and meaning are all derived from the same session identity. Naming is retrieval; sync binding is durability; the assert-finished seam is what makes durability prompt; the tag/note/archive layer is what makes the pile usable in year three. The non-obvious link: immutability is the key that unlocks the completeness gate — a rotated segment is not 'probably done', it is finished forever, which is a stronger claim than any quiescence timer can make, and it is the reason this can be safe rather than a hack.
