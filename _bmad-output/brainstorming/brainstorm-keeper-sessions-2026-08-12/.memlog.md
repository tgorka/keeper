- (technique) started First Principles Thinking
- (idea by coach) bedrock: a session is a directory whose truth is files; keeper adds a lens, never a store — same one-idea as notes vaults
- (idea by coach) bedrock: the session README is the only durable memory of the work; the feature's job is to make writing it during the work cheaper than after
- (idea by coach) the unit of identity is the folder, but identity must survive active/->archive/YYYY/ moves — ULID in README frontmatter, folder path is presentation
- (idea by coach) a session has exactly three lifecycle states on disk already: active, archived (by location), deleted (absent) — UI must not invent a fourth hidden state
- (idea by coach) status 'what is being worked on' is derivable: mtime of newest file per subtree + newest ## Log entry date — no new metadata needed to ship v1 status
- (idea by coach) workspace/ is untracked, so the sync watcher never sees it — session watching needs a second, non-git watcher for workspace freshness
- (idea by coach) freshness split per subtree: workspace activity means 'agent is iterating', artifacts activity means 'something was promoted' — two different signals, show both
- (idea by coach) the Promote table is machine-readable markdown — parse it as the contract for archive-time copying, no new manifest file
- (idea by coach) promotion = copy workspace/X to artifacts/name; archive check = every table row's target exists and is newer-or-equal to its source
- (idea by coach) a session with an empty Promote table and empty artifacts/ at archive time should route to delete-instead offer — the zone rule says so
- (idea by coach) tags/properties live in README frontmatter exactly like notes frontmatter tiers: keeper-owned id/created/pinned, obsidian tags, user fields
- (idea by coach) the sessions flag on a SyncProfile mirrors the notes flag verbatim: profile + subfolder name, default 60-sessions
- (idea by coach) capability gating: CapabilitiesVm.sessions true only when sync capability and at least the flag can be set — absent surface, not broken surface
- (idea by coach) editing a session README or artifact md IS the notes editor on a file outside a vault — reuse the whole editor, not a copy of it
- (idea by coach) quick capture into a session = append a dated entry under ## Log of the chosen active session — capture parity the owner asked for
- (idea by coach) the _template/ folder is data, not config: create-new copies it verbatim; keeper does not own the template contents
- (idea by coach) create-from-previous = copy the previous session's prompts/ and README skeleton (headings, not content) + write continues: ref both ways
- (idea by coach) back-reference field pair: continues: <session-id> in the new one, continued-by: <session-id> appended in the old one — links survive archive moves because they are ids
- (idea by coach) sessions list search reuses the notes query grammar with session fields: is:active is:archived tag: field: date: text: origin:
- (idea by coach) pins are frontmatter pinned: true on the session README — same writer, same byte-preservation promise
- (technique) started Assumption Reversal
- (idea by coach) assume 'keeper never runs the agent' — keep it, but reversal shows the seam: a session row could expose 'copy path' / 'open in terminal' affordances so starting an agent beside it is one click, still not execution
- (idea by coach) assume 'archive is manual' — reversed: keeper could suggest archiving when a session is stale 30d with follow-ups empty; suggestion chip, never auto-move
- (idea by coach) assume 'one active session at a time matters' — reversed: many active sessions across two drives is the real case; the list is multi-vault like notes vault switcher
- (idea by coach) assume 'the README is written by the human' — mostly the agent writes it; so unread marks + origin blame on the session row are the primary review surface, same as notes
- (idea by coach) assume 'workspace is invisible to keeper because untracked' — reversed: keeper can still LIST workspace files read-only (fs walk) to show 'what the agent is doing right now' without ever committing them
- (idea by coach) assume 'template is one' — reversed: _template/ today, but any archived session can act as a pattern; template picker = _template + recent sessions
- (idea by coach) assume 'promote happens at archive' — the zone rule says promote mid-session often; UI needs a promote action on any workspace file at any time, archive just runs the final sweep
- (idea by coach) assume 'sessions are in 60-sessions' — the flag must carry the subfolder name; neuradrive proves the same shape, different drive; never hardcode
- (idea by coach) assume 'a session is text' — refs/ may hold small csv/json; the existing viewer registry (csv/json editors) applies inside a session for free
- (idea by coach) assume 'search is over the README only' — reversed: text search should sweep README + artifacts + prompts + refs (bounded parallel scan like notes_search), workspace excluded by default with an opt-in toggle
- (idea by coach) assume 'archived sessions are dead' — they are the pattern library; archive browse + 'new like this' is the main reuse loop
- (idea by coach) assume 'the log is chronological prose' — each ## Log entry is a capture target; tray shows 'log to session X' beside 'new note'
- (idea by coach) assume 'keeper shows sessions in the main window only' — a tiny 'active session' status could live in the tray menu: name + freshness + open
- (idea by coach) assume 'conflict handling needs new design' — sessions inherit conflict-copy rows from the sync engine; the list shows is:conflict rows like notes

- (technique) started Reverse Brainstorming (how would sessions-in-keeper fail?)
- (idea by coach) failure: keeper scaffolds 60-sessions into a drive that never had it -> inverse: adopt-only; the flag requires picking an existing subfolder or explicit create with confirmation
- (idea by coach) failure: archive moves the folder while an agent is mid-write -> inverse: pre-archive freshness check; warn if workspace changed in the last N minutes, show what is hot
- (idea by coach) failure: promote copies a half-written file (agent still streaming) -> inverse: reuse the sync engine's four-tier stability gate for promote copies
- (idea by coach) failure: two windows edit the same README -> inverse: sessions use the same keyed document store + body channel as notes; no second buffer system
- (idea by coach) failure: session list rescans the whole drive on every change -> inverse: index only <sessions-subfolder>/{active,archive}, cap depth, .keeper cache like the notes index
- (idea by coach) failure: the app invents session state that files cannot express (progress %, status enum) -> inverse: every visible fact must be derivable from files+git; UI state is only lenses
- (idea by coach) failure: archiving with unsynced LFS uploads parks artifacts on one machine -> inverse: archive completes locally and reports sync truthfully via existing journal surface — never blocks, never lies
- (idea by coach) failure: 'create like session X' copies X's content wholesale including stale decisions -> inverse: pattern copy takes structure only (headings, prompts/, refs pointers), never Summary/Log content
- (idea by coach) failure: deleting a session from keeper unlinks files irrecoverably -> inverse: session delete goes through .keeper/trash like notes delete
- (idea by coach) failure: search grammar diverges from notes grammar -> inverse: one parser crate path, sessions adds predicates, never forks
- (idea by coach) failure: the sessions view duplicates the notes editor and drifts -> inverse: panels host the SAME editor component against a session file target; one editor, two lenses
- (idea by coach) failure: workspace watcher burns CPU on a 400GB drive -> inverse: workspace watch only for sessions visible in the list window, coarse mtime polling elsewhere
- (technique) started SCAMPER (on the notes feature as the base)

- (idea by coach) Combine: session + notes: a note can wikilink a session by id; session README links notes; backlinks panel works across both because both are indexed markdown
- (idea by coach) Combine: session + recordings: a recording landing during an active session could be referenced from refs/ (owner's zone rules put media in 40-media, refs point at it)
- (idea by coach) Adapt: journal-today pattern -> session-log-today: one command appends/creates today's dated Log entry in the chosen session and drops the caret there
- (idea by coach) Adapt: spaces-as-saved-queries -> session spaces: 'active', 'archived YYYY', 'stale', 'mine vs agent' ship as default spaces, editable, restorable — same restore-defaults verb
- (idea by coach) Modify/Magnify: the promote table gets a UI: two-column panel workspace|artifacts with per-row promote buttons and staleness (source newer than target) badges
- (idea by coach) Put to other use: capture window on a session README = a sticky 'mission log' floating window during a work sitting
- (idea by coach) Eliminate: no session-level 'open folder in terminal' bespoke tooling beyond reveal — reveal in Finder already exists for notes; reuse verb
- (idea by coach) Reverse: instead of keeper asking 'which template', the template picker previews the actual folder tree + README skeleton it will create — the preview is the documentation (UX-DR45 pattern)
- (idea by coach) Reverse: archive is usually end-of-life; here 'unarchive' must exist too (move back to active/, reopen follow-ups) because the zone rule allows reopening by continuation — decide: continuation preferred, unarchive is the escape hatch
- (insight) converging themes: (1) adopt-not-scaffold + files-are-truth everywhere; (2) reuse notes machinery wholesale (editor, capture, watcher channels, query grammar, frontmatter tiers, trash, viewer registry) — sessions adds a folder-level domain and lifecycle verbs only; (3) the three genuinely new pieces are: session index over a two-subtree zone, the promote/archive airlock with stability gate, and the lineage (continues/continued-by) model; (4) status is derived freshness split by subtree (workspace vs artifacts), never stored state

- (technique) started Constraint Mapping
- (idea by coach) real constraint: workspace/ is gitignored at drive level — keeper cannot rely on git for workspace visibility; fs walk + mtime only; turn into asset: workspace freshness is cheap stat, no git cost
- (idea by coach) real constraint: keeper owns commits on these drives — session verbs (create/archive/promote) are fs mutations that the existing scan picks up; no session-specific git code needed beyond what sync already does
- (idea by coach) real constraint: archive/YYYY move changes every path — links must be id-based (ULID) or repo-root-relative and rewritten; decide: internal session links relative within the session folder (survive the move untouched), cross-zone links repo-root-relative (unaffected by the move)
- (idea by coach) real constraint: two drives, two zones — every IPC call is (profileId|sessionsRootId, sessionId) scoped like (vaultId, noteId)
- (idea by coach) imagined constraint: 'sessions need their own window' — no; sessions are a primary view in the shell like notes, plus capture windows for READMEs
- (idea by coach) imagined constraint: 'need a session daemon' — no; the existing watcher + on-demand fs walks suffice at 60-sessions scale (tens of sessions, not thousands)
- (idea by coach) real constraint: template folder name _template/ sorts first and must never be listed as a session — index skips _template and any name starting with _ or .
- (idea by coach) real constraint: session slugs YYYY-MM-DD-<slug> — creation UI generates the date prefix, slug from title, collision appends counter like note naming
