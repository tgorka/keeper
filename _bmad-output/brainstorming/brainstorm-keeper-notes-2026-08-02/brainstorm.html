## Job to Be Done

What is a keeper user really hiring notes to do?

JTBD-1hired for

Catch a thought in under two seconds without losing the context I am in — the capture job outranks every other job.

JTBD-2hired for

Give my agent and me one shared brain we both write to, in files, so neither of us needs the other's tool.

JTBD-3hired for

Keep what I write in files I own that are already synced everywhere — no vendor, no export, no lock-in.

JTBD-4hired for

Find the thing I wrote three months ago in five seconds, from a fragment I half remember.

JTBD-5 keeper-native

Turn a message I just received into a note without leaving the messenger — keeper is the only note app that is already looking at my conversations.

JTBD-6hired for

Keep a daily ritual (journal) going without ever deciding where today's entry lives.

JTBD-7 keeper-native

See what changed while I was away — by whom, on which machine, and whether it was the agent.

JTBD-8hired for

Park a half-finished thought somewhere it will nag me later — an inbox that is honest about being unfiled.

Insight The keeper-native job is JTBD-5 + JTBD-7: notes sitting beside a Matrix timeline and on top of a git sync engine that already stamps provenance. Nobody else can offer that pair.
Insight JTBD-2 reframes the whole product: if the agent writes most of the words, the primary surface is not an editor, it is a REVIEW surface.

## Trait Transfer

Graft what makes Obsidian, make.md, Apple Notes, Raycast Notes, Bear, Drafts and git itself work.

Obsidian→The folder IS the database. A vault is a plain directory of .md; keeper must be able to point at an existing Obsidian vault and not break it.
Obsidian→Links are typed in the text ([[wikilink]]), so the link graph survives every tool, including a plain text editor.
Obsidian→YAML frontmatter as first-class typed properties, not hidden metadata.
Obsidian→Daily notes with a configurable path template, and a templates folder applied at creation.
Obsidian→Leave .obsidian/ strictly untouched — coexistence is a feature, not an afterthought.
make.md→Spaces — virtual folders defined by a rule/query, not by where the file sits on disk.
make.md→Contexts — a table view over notes where the columns ARE frontmatter fields, editable inline.
make.md→The space definition is itself a note, so the organisation syncs, diffs and is agent-writable like everything else.
make.md→The same note set rendered as list, table, board or calendar — the view is a lens, never a move.
Apple Notes→A tag chip bar that filters by intersection, with a tag browser that shows counts.
Apple Notes→Pinned notes float above the list; pinning is one keystroke and needs no folder.
Apple Notes→An attachments view — every image/file in the vault, browsable without knowing which note holds it.
Raycast Notes→A floating window that never asks where to save and never shows a file path.
Raycast Notes→The panel can be summoned over a full-screen app and dismissed with one key — it is a scratchpad, not an app.
Bear→Hierarchical tags parsed out of the body (#work/clients/acme) so the tag tree needs no separate UI to build.
Drafts→Capture first, triage later — every capture lands somewhere valid before you decide what it is.
Notion→Saved views with their own filters, sort and grouping, nameable and shareable.
git · already in keeper→Per-note history and diff come almost free because the sync engine commits every change with provenance trailers.
Insight Trait transfer's biggest win is the one nobody copies from a note app: keeper already has a commit log per synced file, so note history, blame and "what did the agent change" are a projection of something that already exists.

## Assumption Reversal

List every assumption and flip it. Each card holds the received wisdom struck through on top — Reverse it across the hinge and the bottom half is what we are building instead.

Assumptionnotes live in a notes app
↻
Notes live in the tray; the main window is the optional surface, the popover is the product.
Assumptionyou choose a folder when you create a note
↻
Nothing is ever filed at creation; organisation is entirely retroactive and virtual.
Assumptionthe editor is the primary pane
↻
The filtered list is primary; the editor is what happens after you found the note.
Assumptionthe user writes the notes
↻
The agent writes most of them and the user curates; design for reading and accepting, not typing.
Assumptionsync is invisible plumbing
↻
Sync is visible provenance on every row: this note last touched by hesperia, 2 minutes ago, by the agent.
Assumptiontags are metadata
↻
Tags are the filesystem; the physical tree is the thing you hide by default.
Assumptiona vault is a setting
↻
A vault is a sync element; you get vaults by flagging folders you already sync, and you get zero new configuration surface.
Assumptionmarkdown must be rendered separately
↻
Editing IS the rendering; live preview with source revealed only on the line under the cursor.
Assumptionnotes need a database
↻
The index is a disposable cache; delete it and it rebuilds from the files in seconds.
Assumptionattachments need a server
↻
Keeper already ships a custom URI scheme handler for local media; images in notes cost nothing new.
Assumptionsearch needs an engine
↻
For a personal vault, a bounded parallel scan of a few thousand small files beats a heavy index and never goes stale.
Assumptionconflicts are errors
↻
A conflict is a note with two surviving bodies side by side; the user picks in the editor, never in a modal.
Insight · load-bearing Two reversals compound into the core architecture: vault = flagged sync element (no new config), index = disposable cache (no new database). The feature adds a lens, not a store.

## TRIZ Contradiction

Name each core contradiction and win both sides. No trade-offs accepted.

Contradiction A
rich organisation
VS
plain-file portability
Win bothPhysical layout stays whatever the vault already is; organisation is a virtual index rebuilt from frontmatter, tags and links, and every space definition is itself a plain note.
Contradiction B
instant capture
VS
correct filing
Win bothCapture always lands in a valid place (today's journal or a dated inbox note) and the SAME panel offers one-keystroke retro-filing once the words exist.
Contradiction C
the agent writes
WHILE
the user types
Win bothWatch the file; if the buffer is clean, apply live with a fading highlight; if dirty, merge non-overlapping hunks and surface an inline "agent changed this" bar with a diff, never a modal.
Contradiction D
sync every keystroke
VS
do not create a commit storm
Win bothDebounce to a local commit on two seconds of idle, coalesce a burst into one commit, push on a longer timer or on window blur, and force-flush on hide and on quit.
Contradiction E
many vaults
VS
one mental model
Win bothOne switcher, vault-scoped everything, and the switch is a filter change rather than a reload.
Contradiction F
a light webview
VS
a real editor
Win bothThe quick-capture panel is a plain textarea that paints instantly; the full editor is a lazily loaded chunk that only the main window ever pays for.
Contradiction G
Obsidian compatibility
VS
keeper's own features
Win bothEvery keeper concept is expressed in frontmatter keys and folders Obsidian already tolerates; keeper-specific state lives in an ignored cache directory.

## Crank the Dial to 11

Exaggerate usability until something breaks open.

11
usability — pinned
  1. One global hotkey to capture, from anywhere, over any app, even full screen — the panel is up and focused in well under a second.
  2. No save button anywhere in the product; Escape means saved and gone; closing the window means saved.
  3. No title dialog ever — the first line is the title, the filename is a slug with a date prefix, and a collision just appends a counter.
  4. The capture panel restores the exact caret position of the sentence you abandoned.
  5. Typing # offers the tag tree inline; typing [[ offers notes and creates the missing one on Enter; typing / opens a command menu of templates, blocks, dates and diagrams.
  6. Pasting an image writes it into the vault attachments folder and drops an embed — no dialog, no picker.
  7. Dragging a file in from the same synced folder produces a relative link rather than a copy.
  8. The tray icon menu carries New Note, Today's Journal and the last five touched notes, so the app window is optional for a whole day of use.
  9. The tray glyph gains a subtle dot when the agent has touched notes you have not read.
  10. A note can be torn off into a small always-on-top sticky window, and several stickies can live at once.
  11. Every filter you build is one keystroke from becoming a saved space.
  12. The command palette answers note queries directly: type a fragment and the top hits are notes, not commands.
  13. Backlinks are always visible at the foot of the editor and cost nothing to maintain because they are derived.
  14. Mermaid renders as you type, and a broken diagram shows the error inline instead of vanishing.
  15. The list can group by any frontmatter field, so a board view is a grouping choice rather than a separate feature.

## Backcasting

Fix the finished moment and walk back to the first move. Read top to bottom — time runs backwards.

◀◀ REWIND
The finished moment

Hit the hotkey over a full-screen window, type two sentences, press Escape; two seconds later the file exists in the synced vault; thirty seconds later it is pushed; the other machine has it; the agent edits it overnight; the tray shows a dot ; one click shows the diff; Accept clears the dot.

◀ Back one step

The dot and the diff require per-note history, which requires the sync engine to expose a per-file commit log with its provenance trailers.

◀ Back two

The other machine has it because the vault is a sync element with an auto-sync cadence.

◀ Back three

The file exists because a vault writer resolved the active vault and applied the journal or inbox naming rule.

◀ Back four

The panel exists because a second global hotkey and a small always-on-top webview window exist.

First move — start here

Mark a sync element as notes and model the vault in Rust. Nothing above it is honest without that.

## Constraint Mapping

Sort the real constraints from the imagined ones and turn each into an asset.

■ Real — and therefore useful

All logic must live in Rust and the frontend is a pure renderer of view models.
AssetThe notes index, parser, tag tree and link graph become a testable pure core module with no UI in it.
keeper-core must stay tauri-free AND sync-free.
AssetThe notes domain (frontmatter, tags, links, templates, naming) lands in keeper-core as pure functions, and everything touching the filesystem or git lives above it.
No AGPL/GPL dependency, cargo-deny enforced.
Assetmermaid (MIT) and CodeMirror 6 (MIT) both pass, so the two heavyweight UI capabilities are legal.
No large payloads over IPC.
AssetNote bodies stream per open note, lists carry only view models, and images go through the existing custom URI scheme.

□ Imagined — dissolved on contact

Notes need a full-text search engine.
RealityA bounded parallel scan over a personal vault answers in tens of milliseconds and is never stale.
The editor must be a rich text editor.
RealityMarkdown with live preview is what the target user already wants, and it keeps the file honest.
We must invent a sync mode for notes.
RealityA cadence knob on an existing sync element is the whole feature.

## Failure Analysis

Dissect how comparable features fail in the wild, and bank the lesson.

✕
Evernote-style apps rot because export is lossy.
LessonThe file on disk is the product, and there is nothing to export.
✕
Obsidian sync conflicts produce duplicate files nobody reconciles.
LessonSurface conflicts in the note list as first-class rows, not as litter on disk.
✕
Quick-capture tools lose text when the panel is dismissed by accident.
LessonThe buffer persists across dismissals and process restarts before it is ever a file.
✕
Tag systems die because adding a tag costs a dialog.
LessonInline # with completion, and nothing else.
✕
Virtual folder systems confuse users about where the file really is.
LessonEvery virtual row can reveal the real path on demand, and the physical tree is always one click away.
✕
File watchers miss editor-atomic renames and the UI goes stale.
LessonTreat rename-into-place as a modification, and reconcile on window focus as a backstop.

## Build on What Works

Amplify what keeper already does well. Left column: already paid for. Right column: what notes get for free.

✓
Keeper already composes one status line in Rust so the tray and the window can never word it differently.
Do the same for notes: one Rust-composed note view model feeds list, palette and tray.
✓
Keeper already has a palette-and-native-menu registry that cannot drift.
Add every note action there and get the menu, the cheat sheet and the palette for free.
✓
Keeper already has a conflict model with surviving copies.
Reuse it verbatim for notes rather than inventing note-specific merge.
✓
Keeper already stamps provenance trailers on every sync commit.
Project them into the note row as "who and where", for free.
✓
Keeper already serves local media over a custom scheme.
Reuse it for note attachments rather than base64 over IPC.
✓
Keeper already gates capabilities per platform.
Add a notes capability so the iOS shell can omit the whole surface without dead code.

Verdicts

Architecture verdictdecided
The notes domain (frontmatter, tags, links, templates, naming, index) is pure and lands in keeper-core; the filesystem watcher, vault IO and git cadence live in the keeper shell over keeper-sync; the webview is a pure renderer of note view models.
Storage verdictdecided
A vault is an ordinary Obsidian-shaped directory inside a synced element: attachments/, journal/, templates/, spaces/, flat notes at the root; keeper's index cache lives in .keeper/ and is never committed.
Identity verdictdecided
Every note carries a ULID id in frontmatter so links, pins and history survive a rename; the filename stays human and Obsidian-native.
Concurrency verdictdecided
Never lock a note; watch it. Clean buffer applies the external write live with a fading highlight; dirty buffer merges non-overlapping hunks and raises an inline diff bar.
Linux parity verdict — blocking prerequisitemust fix first
The tray is the primary surface, so the existing macOS-template tray glyphs and the swap-the-whole-menu tray strategy must be fixed for Linux before notes can rely on them.

Non-obvious links

◆

The agent-cohabitation cluster is almost entirely a projection of the sync engine's existing commit provenance — the most differentiating cluster is also the cheapest.

◆

“Capture with no filing” (cluster 1) and “organisation is virtual” (cluster 3) are one idea wearing two hats — because nothing is filed at creation, the virtual lens is not a nicety, it is the only organisation that exists.

◆

The vault-as-sync-element decision quietly deletes an entire settings surface, a vault picker, a path validator and a migration story.

The wildcard that turns out to be the breakthrough

“The tray glyph gains a dot when the agent touched notes you have not read.”
It makes an invisible collaborator visible, and it is the one thing no existing note app does.
