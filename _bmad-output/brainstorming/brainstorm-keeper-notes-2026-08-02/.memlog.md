- (technique) started Job to Be Done — what is a keeper user really hiring notes to do
- (idea) JTBD-1 Catch a thought in under two seconds without losing the context I am in — the capture job outranks every other job
- (idea) JTBD-2 Give my agent and me one shared brain we both write to, in files, so neither of us needs the other's tool
- (idea) JTBD-3 Keep what I write in files I own that are already synced everywhere — no vendor, no export, no lock-in
- (idea) JTBD-4 Find the thing I wrote three months ago in five seconds, from a fragment I half remember
- (idea) JTBD-5 Turn a message I just received into a note without leaving the messenger — keeper is the only note app that is already looking at my conversations
- (idea) JTBD-6 Keep a daily ritual (journal) going without ever deciding where today's entry lives
- (idea) JTBD-7 See what changed while I was away — by whom, on which machine, and whether it was the agent
- (idea) JTBD-8 Park a half-finished thought somewhere it will nag me later — an inbox that is honest about being unfiled
- (insight) The keeper-native job is JTBD-5 + JTBD-7: notes sitting beside a Matrix timeline and on top of a git sync engine that already stamps provenance. Nobody else can offer that pair
- (insight) JTBD-2 reframes the whole product: if the agent writes most of the words, the primary surface is not an editor, it is a REVIEW surface
- (technique) started Trait Transfer — graft what makes Obsidian, make.md, Apple Notes, Raycast Notes, Bear, Drafts and git itself work
- (idea) From Obsidian: the folder IS the database. A vault is a plain directory of .md; keeper must be able to point at an existing Obsidian vault and not break it
- (idea) From Obsidian: links are typed in the text ([[wikilink]]), so the link graph survives every tool, including a plain text editor
- (idea) From Obsidian: YAML frontmatter as first-class typed properties, not hidden metadata
- (idea) From Obsidian: daily notes with a configurable path template, and a templates folder applied at creation
- (idea) From Obsidian: leave .obsidian/ strictly untouched — coexistence is a feature, not an afterthought
- (idea) From make.md: Spaces — virtual folders defined by a rule/query, not by where the file sits on disk
- (idea) From make.md: Contexts — a table view over notes where the columns ARE frontmatter fields, editable inline
- (idea) From make.md: the space definition is itself a note, so the organisation syncs, diffs and is agent-writable like everything else
- (idea) From make.md: the same note set rendered as list, table, board or calendar — the view is a lens, never a move
- (idea) From Apple Notes: a tag chip bar that filters by intersection, with a tag browser that shows counts
- (idea) From Apple Notes: pinned notes float above the list; pinning is one keystroke and needs no folder
- (idea) From Apple Notes: an attachments view — every image/file in the vault, browsable without knowing which note holds it
- (idea) From Raycast Notes: a floating window that never asks where to save and never shows a file path
- (idea) From Raycast Notes: the panel can be summoned over a full-screen app and dismissed with one key — it is a scratchpad, not an app
- (idea) From Bear: hierarchical tags parsed out of the body (#work/clients/acme) so the tag tree needs no separate UI to build
- (idea) From Drafts: capture first, triage later — every capture lands somewhere valid before you decide what it is
- (idea) From Notion: saved views with their own filters, sort and grouping, nameable and shareable
- (idea) From git (already in keeper): per-note history and diff come almost free because the sync engine commits every change with provenance trailers
- (insight) Trait transfer's biggest win is the one nobody copies from a note app: keeper already has a commit log per synced file, so note history, blame and 'what did the agent change' are a projection of something that already exists
- (technique) started Assumption Reversal — list every assumption and flip it
- (idea) Reverse 'notes live in a notes app' -> notes live in the tray; the main window is the optional surface, the popover is the product
- (idea) Reverse 'you choose a folder when you create a note' -> nothing is ever filed at creation; organisation is entirely retroactive and virtual
- (idea) Reverse 'the editor is the primary pane' -> the filtered list is primary; the editor is what happens after you found the note
- (idea) Reverse 'the user writes the notes' -> the agent writes most of them and the user curates; design for reading and accepting, not typing
- (idea) Reverse 'sync is invisible plumbing' -> sync is visible provenance on every row: this note last touched by hesperia, 2 minutes ago, by the agent
- (idea) Reverse 'tags are metadata' -> tags are the filesystem; the physical tree is the thing you hide by default
- (idea) Reverse 'a vault is a setting' -> a vault is a sync element; you get vaults by flagging folders you already sync, and you get zero new configuration surface
- (idea) Reverse 'markdown must be rendered separately' -> editing IS the rendering; live preview with source revealed only on the line under the cursor
- (idea) Reverse 'notes need a database' -> the index is a disposable cache; delete it and it rebuilds from the files in seconds
- (idea) Reverse 'attachments need a server' -> keeper already ships a custom URI scheme handler for local media; images in notes cost nothing new
- (idea) Reverse 'search needs an engine' -> for a personal vault, a bounded parallel scan of a few thousand small files beats a heavy index and never goes stale
- (idea) Reverse 'conflicts are errors' -> a conflict is a note with two surviving bodies side by side; the user picks in the editor, never in a modal
- (insight) Two reversals compound into the core architecture: vault = flagged sync element (no new config), index = disposable cache (no new database). The feature adds a lens, not a store
- (technique) started TRIZ Contradiction — name each core contradiction and win both sides
- (idea) Contradiction A: rich organisation vs plain-file portability. Win both — physical layout stays whatever the vault already is; organisation is a virtual index rebuilt from frontmatter, tags and links, and every space definition is itself a plain note
- (idea) Contradiction B: instant capture vs correct filing. Win both — capture always lands in a valid place (today's journal or a dated inbox note) and the SAME panel offers one-keystroke retro-filing once the words exist
- (idea) Contradiction C: the agent writes while the user types. Win both — watch the file; if the buffer is clean, apply live with a fading highlight; if dirty, merge non-overlapping hunks and surface an inline 'agent changed this' bar with a diff, never a modal
- (idea) Contradiction D: sync every keystroke vs do not create a commit storm. Win both — debounce to a local commit on two seconds of idle, coalesce a burst into one commit, push on a longer timer or on window blur, and force-flush on hide and on quit
- (idea) Contradiction E: many vaults vs one mental model. Win both — one switcher, vault-scoped everything, and the switch is a filter change rather than a reload
- (idea) Contradiction F: a light webview vs a real editor. Win both — the quick-capture panel is a plain textarea that paints instantly; the full editor is a lazily loaded chunk that only the main window ever pays for
- (idea) Contradiction G: Obsidian compatibility vs keeper's own features. Win both — every keeper concept is expressed in frontmatter keys and folders Obsidian already tolerates; keeper-specific state lives in an ignored cache directory

- (technique) started Crank the Dial to 11 — exaggerate usability until something breaks open
- (idea) One global hotkey to capture, from anywhere, over any app, even full screen — the panel is up and focused in well under a second
- (idea) No save button anywhere in the product; Escape means saved and gone; closing the window means saved
- (idea) No title dialog ever — the first line is the title, the filename is a slug with a date prefix, and a collision just appends a counter
- (idea) The capture panel restores the exact caret position of the sentence you abandoned
- (idea) Typing # offers the tag tree inline; typing [[ offers notes and creates the missing one on Enter; typing / opens a command menu of templates, blocks, dates and diagrams
- (idea) Pasting an image writes it into the vault attachments folder and drops an embed — no dialog, no picker
- (idea) Dragging a file in from the same synced folder produces a relative link rather than a copy
- (idea) The tray icon menu carries New Note, Today's Journal and the last five touched notes, so the app window is optional for a whole day of use
- (idea) The tray glyph gains a subtle dot when the agent has touched notes you have not read
- (idea) A note can be torn off into a small always-on-top sticky window, and several stickies can live at once
- (idea) Every filter you build is one keystroke from becoming a saved space
- (idea) The command palette answers note queries directly: type a fragment and the top hits are notes, not commands
- (idea) Backlinks are always visible at the foot of the editor and cost nothing to maintain because they are derived
- (idea) Mermaid renders as you type, and a broken diagram shows the error inline instead of vanishing
- (idea) The list can group by any frontmatter field, so a board view is a grouping choice rather than a separate feature
- (technique) started One Feature Only — keep exactly one capability and make it unbelievably good
- (idea) The one feature is tray quick capture that writes a markdown file into an already-synced vault. Everything else in this session is elaboration on it
- (insight) One Feature Only fixes the epic ordering: the first user-visible story must be capture-to-file, and the vault model exists only to make that story honest
- (technique) started Backcasting — fix the finished moment and walk back to the first move
- (idea) Finished moment: hit the hotkey over a full-screen window, type two sentences, press Escape; two seconds later the file exists in the synced vault; thirty seconds later it is pushed; the other machine has it; the agent edits it overnight; the tray shows a dot; one click shows the diff; Accept clears the dot
- (idea) Back one step: the dot and the diff require per-note history, which requires the sync engine to expose a per-file commit log with its provenance trailers
- (idea) Back two: the other machine has it because the vault is a sync element with an auto-sync cadence
- (idea) Back three: the file exists because a vault writer resolved the active vault and applied the journal or inbox naming rule
- (idea) Back four: the panel exists because a second global hotkey and a small always-on-top webview window exist
- (idea) First move: mark a sync element as notes and model the vault in Rust. Nothing above it is honest without that
- (technique) started Worst Possible Idea — generate terrible designs and flip each
- (idea) Terrible: a modal that asks for title, folder and tags before you can type. Flip: never block the first keystroke; ask nothing, ever
- (idea) Terrible: store notes in keeper.db so they are fast. Flip: files are the product; the database is a cache that can be deleted
- (idea) Terrible: lock the file while the editor is open so the agent cannot corrupt it. Flip: expect concurrent writes and make the merge visible and cheap
- (idea) Terrible: a proprietary keeper-note format with extensions Obsidian cannot read. Flip: everything expressible in vanilla frontmatter and standard markdown
- (idea) Terrible: sync notes only when the user presses a button. Flip: notes are the one element type where auto-sync is on by default
- (idea) Terrible: one giant vault for everything. Flip: vaults are cheap, scoped to a sync element, and switching is a filter
- (idea) Terrible: render markdown in a separate preview pane you must toggle. Flip: live preview, source only on the active line
- (technique) started Constraint Mapping — sort the real constraints from the imagined ones and turn each into an asset
- (idea) Real: all logic must live in Rust and the frontend is a pure renderer of view models. Asset — the notes index, parser, tag tree and link graph become a testable pure core module with no UI in it
- (idea) Real: keeper-core must stay tauri-free AND sync-free. Asset — the notes domain (frontmatter, tags, links, templates, naming) lands in keeper-core as pure functions, and everything touching the filesystem or git lives above it
- (idea) Real: no AGPL/GPL dependency, cargo-deny enforced. Asset — mermaid (MIT) and CodeMirror 6 (MIT) both pass, so the two heavyweight UI capabilities are legal
- (idea) Real: no large payloads over IPC. Asset — note bodies stream per open note, lists carry only view models, and images go through the existing custom URI scheme
- (idea) Imagined: notes need a full-text search engine. Reality — a bounded parallel scan over a personal vault answers in tens of milliseconds and is never stale
- (idea) Imagined: the editor must be a rich text editor. Reality — markdown with live preview is what the target user already wants, and it keeps the file honest
- (idea) Imagined: we must invent a sync mode for notes. Reality — a cadence knob on an existing sync element is the whole feature
- (technique) started Empathy Map — what the user says, thinks, does and feels around notes in keeper
- (idea) Says: I want it handy. Reads as — the cost of capture must round to zero, and every other feature is negotiable
- (idea) Thinks: my notes should outlive this app. Reads as — plain files, Obsidian-shaped, verifiable on disk
- (idea) Does: keeps the app in the menu bar all day and rarely opens the window. Reads as — the tray is the primary surface and must carry real actions
- (idea) Feels: uneasy when an agent edits things silently. Reads as — every agent write needs an unread mark and a reviewable diff

- (technique) started Failure Analysis — dissect how comparable features fail in the wild
- (idea) Failure: Evernote-style apps rot because export is lossy. Lesson — the file on disk is the product, and there is nothing to export
- (idea) Failure: Obsidian sync conflicts produce duplicate files nobody reconciles. Lesson — surface conflicts in the note list as first-class rows, not as litter on disk
- (idea) Failure: quick-capture tools lose text when the panel is dismissed by accident. Lesson — the buffer persists across dismissals and process restarts before it is ever a file
- (idea) Failure: tag systems die because adding a tag costs a dialog. Lesson — inline # with completion, and nothing else
- (idea) Failure: virtual folder systems confuse users about where the file really is. Lesson — every virtual row can reveal the real path on demand, and the physical tree is always one click away
- (idea) Failure: file watchers miss editor-atomic renames and the UI goes stale. Lesson — treat rename-into-place as a modification, and reconcile on window focus as a backstop
- (technique) started Build on What Works — amplify what keeper already does well
- (idea) Keeper already composes one status line in Rust so the tray and the window can never word it differently. Do the same for notes: one Rust-composed note view model feeds list, palette and tray
- (idea) Keeper already has a palette-and-native-menu registry that cannot drift. Add every note action there and get the menu, the cheat sheet and the palette for free
- (idea) Keeper already has a conflict model with surviving copies. Reuse it verbatim for notes rather than inventing note-specific merge
- (idea) Keeper already stamps provenance trailers on every sync commit. Project them into the note row as 'who and where', for free
- (idea) Keeper already serves local media over a custom scheme. Reuse it for note attachments rather than base64 over IPC
- (idea) Keeper already gates capabilities per platform. Add a notes capability so the iOS shell can omit the whole surface without dead code

- (decision) Architecture verdict — notes domain (frontmatter, tags, links, templates, naming, index) is pure and lands in keeper-core; the filesystem watcher, vault IO and git cadence live in the keeper shell over keeper-sync; the webview is a pure renderer of note view models
- (decision) Storage verdict — a vault is an ordinary Obsidian-shaped directory inside a synced element: attachments/, journal/, templates/, spaces/, flat notes at the root; keeper's index cache lives in .keeper/ and is never committed
- (decision) Identity verdict — every note carries a ULID id in frontmatter so links, pins and history survive a rename; the filename stays human and Obsidian-native
- (decision) Concurrency verdict — never lock a note; watch it. Clean buffer applies the external write live with a fading highlight; dirty buffer merges non-overlapping hunks and raises an inline diff bar
- (decision) Linux parity verdict — the tray is the primary surface, so the existing macOS-template tray glyphs and the swap-the-whole-menu tray strategy must be fixed for Linux before notes can rely on them
- (insight) Non-obvious link: the agent-cohabitation cluster is almost entirely a projection of the sync engine's existing commit provenance — the most differentiating cluster is also the cheapest
- (insight) Non-obvious link: 'capture with no filing' (cluster 1) and 'organisation is virtual' (cluster 3) are one idea wearing two hats — because nothing is filed at creation, the virtual lens is not a nicety, it is the only organisation that exists
- (insight) Non-obvious link: the vault-as-sync-element decision quietly deletes an entire settings surface, a vault picker, a path validator and a migration story
- (insight) The wildcard that turns out to be the breakthrough: 'the tray glyph gains a dot when the agent touched notes you have not read'. It makes an invisible collaborator visible, and it is the one thing no existing note app does
