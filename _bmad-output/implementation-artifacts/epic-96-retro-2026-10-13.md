### 96.1 — A sandboxed `run`

- **`agents-96-run`: #482, open, final `143c5759`.** It was built at `55069802` on 2026-10-06 and converged at `9cbdf219` on 2026-10-09 (R301). It was restacked to `02827329`, cascaded onto `agents-ci-green`, and amended for clippy 1.99 and then by lane CI486 (stack-notes 2026-10-11 02:00 and CI486c).
  - **What a person gets:** an agent whose `agent.toml` allows `run` can run a program on a host that offers `sandbox`. The program is an argv, never a shell string. On electra it runs under landlock and seccomp; on the Mac it runs under `sandbox-exec`. It writes only its session's `workspace/`, with an empty `HOME` and `TMPDIR` of its own. The approval card shows the argv as it will run, each wrapper between, the drives it reads, the time limit, and each file the session holds (a script, a root dotfile, a git hook) with its hash. For a networked run, the card also shows the workspace files the approval releases. The tiers:
    - T2: a plain run;
    - T3: a run with network;
    - T4: code the session holds;
    - T5: `sudo` and the like, which are refused.

    A drift between the approval and the run (the program, the folder or the workspace) refuses.
  - **Proved:**
    - #1–#17 by the tests the As built table names.
    - The Linux half ran on the dev host: kernel 6.17.0-41 with landlock ABI 7, inside Docker. No Linux CI job exists (DW-395).
    - The Mac half ran on hesperia (macOS 27.0) through lane CI486's `cargo nextest`, 6514/6514 at the tip. That covers `run_macos::{run_timeout_kills_the_process_group, no_process_information_and_no_keychain, the_network_follows_the_plan}` (report-ci486.md § hesperia).
    - #17 by `cargo deny`: landlock 0.4.7, seccompiler 0.5.0, nix 0.31.3.
  - **Built differently:**
    - The Mac's `[sandbox]` table and its Settings moved to rung mcp-mac (R213).
    - A networked Mac run keeps one Unix-socket exception, the system resolver (R231).
    - `sbpl` lets a process read its own information and denies `kern.procargs` (CI486; DW-1192 closed).
  - **Owed:**
    - on electra's host OS, `keeper-agentd status` and the `--ignored` #4(j) kernel test;
    - the operator's own `check:rust:macos` tick on hesperia.

### 96.2 — MCP servers per agent

- **`agents-96-mcp`: #483, open, final `03b1d670`.** It was built at `b1b3406a` on 2026-10-07 and converged at `6172df51` (R274). It converged again at `29424746` after its restack (R307), then was amended by CI486.
  - **What a person gets:** an operator names MCP servers in `agentd.toml` `[[mcp]]`, each a URL or a program. An agent that lists a server in `[tools].mcp` is offered its tools while the server answers. Nothing a drive, a session or a project file names (`.mcp.json`, `opencode.json`) is ever read.
    - Every result and error is outside content: labelled `untrusted` and read by the server's `readers`.
    - A call is checked against those readers before anything leaves.
    - Tiers come from a role's table or the person's rows. Annotations count only when the person trusts them, and a program server is never below T2.
    - An approval binds the program's SHA-256 or the URL's host, plus the tool's definition. A change refuses.
  - **Proved:**
    - #1–#9 and #12 by `agent_turns parks::mcp::*` against real rmcp servers over HTTP and as a child process.
    - #10 for agentd by `docs/egress.md`; #11 is mcp-mac's.
    - One reqwest (0.13.4), and `cargo deny` passes (R157).
  - **Built differently:**
    - A server with a pinned certificate was not connected until the KVM rung's verifier existed (R221, superseded by R320; DW-810 closed).
    - An MCP approval has `once` scope only (R222).
    - A nudge's review pass cannot call a server (R306).
  - **Owed:**
    - no device run for agentd's half (report-96mcp.json);
    - the audit-write failure path is unproved (DW-851).
- **`agents-96-mcp-mac`: #484, open, final `ca4edb39`.** It was built at `65248172` on 2026-10-07 and converged at `232f91dc` (R284). It was restacked to `4099a6d7` (R308) and only rebased since.
  - **What a person gets:**
    - Settings › Agents › *MCP servers* adds, edits and removes the Mac's servers. They are stored in `keeper.db`, and each token is kept in the keychain under a new key for every save.
    - For each server it shows whether the server answers, the program it started as, and its tools' tiers.
    - Settings › Agents › *Sandbox* keeps the Mac's `run` table: `read_exec` folders and environment entries.
    - The egress list names each server by its host or its program.
  - **Proved:**
    - on Linux: the store, a keychain fake, and a real HTTP endpoint checking the saved token, URL, rotation and removal;
    - vitest;
    - Chrome over the mock shell, at a 1280 px window and a real 420 px viewport;

### 96.3 — Coding through Paseo

- **`agents-96-paseo`: #485, open, final `6f0dfc8a`.** It was built at `b87973c8` on 2026-10-07 and converged twice: at `5622e297` (R294) and, after its second restack, at `65dfe2bf` (R312). It was final at `37ce6aa2` before the cascade and only rebased since.
  - **What a person gets:** a coding agent starts a coding run through makistack's Paseo broker only with a person's approval, every time.
    - The approval is T3 with scope once. It is T4 when the run is delegated or unattended, and refused outright in an untrusted session.

    - The starting conversation is told the pull-request link once.
    - No repository credential, token or diff enters a session, a log or an artifact.
  - **Proved:**
    - #1–#7 by keeper-agent tests against a fixture server serving the broker's recorded `tools/list` (`paseo-tools-2025-06-18.json`).

### 96.5 — Another machine through a KVM

- **`agents-96-kvm`: #488, open, final `e0276d20`.** It was built at `1318feda` on 2026-10-11 and fixed under R323 at `4bfc9f0a`. It was restacked to `d30deaa5` onto screen, and the R328 fixes made `e0276d20`.
  - **What a person gets:** an agent on a Linux host can take a snapshot of another machine through a classic NanoKVM. The TLS connection is pinned to the certificate's SHA-256. The agent can send clicks, keys, typing, paste or a power press as a `kvm_act`:
    - Each act is T4 with one approval, decided on another device. It is T5, and refused, for a password, a card number or Ctrl+Alt+Delete.
    - Before the first input, the act is checked against the tiles of a fresh frame.
    - The answer is "sent, effect unverified", with a fresh frame.
    - A NanoKVM-Go is offered its screenshot only.
  - **Proved:**
